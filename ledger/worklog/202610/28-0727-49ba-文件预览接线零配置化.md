## 背景

用户 2026-10-28 问「消费方为什么一定要内联 inject 把服务存起来、为什么还要自己写 flex 行」，拍板两条：
① 读文件服务该由核心接线（`connectHost` 已有先例，同 `workspaceList`）；
② `mount` 那层不该要求消费方自己写样式，「加个标签就行」。目标口径 = 消费方只写
`connectHost(ctx)` + `openFilePreview({ mount, path })`。

- 未验证：宿主 profile 是否都挂 `remote.workspaceFiles`；没挂时现在只留痕 + 不打开（无降级）。

## 下一步

## 结论

- 消费方口径落到两句：`connectHost(ctx)` 一次接线；`openFilePreview({ mount, path })`。
  live 验证：`pnpm build` / `typecheck` 干净、`pnpm test` 128/129（唯一红的是既有 version-sync：
  核心 0.7.0 ≠ demo 0.6.1，来自发版提交 757a8a6，与本任务无关）、`codelint` 全过。
- 留坑：核心 store 无订阅（服务晚到时已打开的预览不会自己恢复）；`mount` 若是调用方刻意用的
  非 flex 布局（如 grid），只补 `display:flex` 时会被改，关闭即还原。
