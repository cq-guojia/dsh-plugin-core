## 背景

用户 2026-10-28 提出要一个「组合下拉选择框」：两个选择器绑定在一起、**视觉上连成一体**，
用来替掉「两个独立下拉框各写联动」的体验（独立框做联动，用户看着就是两个东西，体验不好）。

需求原话要点：

- **联动不写死在组件里**：选了第一个之后发一个事件，由调用方决定第二个是什么内容；需要能拿到返回/回调。
- **一体感**：不能是「两个框拼在一起还有缝」，要像日期范围那样，中间用一条窄分隔连起来，左右不留缝。
- **形态一 = 滑块 + 下拉**：
  - 左侧滑块（Segmented）可能有 2 / 3 / 4 段；
  - 支持单选和多选，**默认单选**；多选参照 demo 里那种「1、2、3、4、5 都能选」的用法；
  - 右侧接一个下拉，允许带搜索、允许分组。
- **形态二 = 两个纯下拉**：左右拼接，中间一条分隔（一条线 或 小横杠），整体一个外框。

用户同时提的问题（待拍板）：这东西该做成「一个固定的组合控件」，还是做成「一个外壳，让调用方
自己往里塞控件（滑块、下拉随便）」？用户的倾向是 **只做外包装**：内部仍用原控件，
样式在外层整合，选中事件用原控件自带的 onChange 绑 —— 需要给出这个方案是否可信的判断。

本轮只读调研已确认的可复用事实：

- `src/ui/Segmented.ts:89-104`：单选 / `multiple` 多选两条受控通道已存在，`onChange` 直接可用。
- `src/ui/Picker.ts:25-51`：`options`/`groups`、`searchable`、`mode: single|multiple`、受控 `value/onChange` 齐全，可作右侧下拉。
- 一体化外观已有现成范式：日期范围的 `DateTimePicker.ts:456-463` 是一个外层触发器里放
  `__pair-group` + `__pair-date` + `__pair-sep`，CSS 见 `src/ui/controls/datetime.css:22-33`；
  `field.css:52-65`（PrefixedInput）、`field.css:67-83`（NumberInput）用的是同一手法：
  外壳持边框/圆角/`overflow:hidden`，内件去边框、靠 `border-right` 当分隔。
- 尺寸轴天然对齐：Segmented 总高 = control-h（`segmented.css:12-15`），Picker 触发器高也是 control-h
  （`picker.css:5,27-29`），拼接不需要改任何一方的高度。
- 缺的只有「外壳」这一层：`src/ui/index.ts` 里没有通用 InputGroup / FieldGroup。

## 待办

- 形态二中间分隔形态：1px 竖线 vs 22px 小横杠块（日期 range 用的是后者）。
- 新控件落位（`src/ui/` 还是 `src/ui/controls/`）、新 CSS 文件 + `gen-css` 产物、demo 页、文档槽位。

已拍板（用户 2026-10-28）：

- **只做两格**，不做多格（「先不允许多用格，没有什么意义，就是两个组合」）。
- **外壳不关心内部语义**：联动由消费方在各自 onChange 里改另一格的值，外壳不持状态、不出联动回调。
- **核心是样式一体**：外壳负责边框、圆角、中间分隔、整体聚焦圈。
- 因此不是两个控件，而是**一个外壳**，形态一（滑块+下拉）与形态二（下拉+下拉）都是它。

## 结论

做成了一个只有样式职责的两格外壳 `SplitGroup`（不是「固定组合控件」）：外框 / 圆角 / 中间 1px 分隔 /
整体 `:focus-within` 圈由外壳画，内件仍是原来的 `Segmented` / `Picker`，联动由消费方在各自
`onChange` 里绑。形态一与形态二共用同一个外壳，差别只是往里放什么。

踩坑（都在本轮解决）：

- `h(SplitGroup, null, a, b)` 要成立，`children` 必须声明为可选 `ReactNode`（全仓惯例同此）；
  写成必需元组 `[ReactNode, ReactNode]` 会让 `h` 的 props 类型报缺 children，且 `...props.children` 报 TS2488。
- demo 里 `h(Segmented, { ... onChange: (v) => … })` 的箭头参数会被推断成隐式 any（泛型组件推断不到），
  要显式标 `(v: string)`。
- 外壳内 Segmented 的 `padding:3px` **不能压成 0**：它是高度契约（3 + item + 3 = control-h），
  正好等于同档 Picker 触发器高；`bordered` 那档还要把让给描边的 1px 还回 padding，否则矮 2px。

留的坑：`split-group.css` 靠后代选择器压 `.dshpc-picker__trigger` / `.dshpc-seg`，**内件改名即静默失效**，
无自检覆盖（已写进 `docs/design/style.md` 与 CSS 注释）。
