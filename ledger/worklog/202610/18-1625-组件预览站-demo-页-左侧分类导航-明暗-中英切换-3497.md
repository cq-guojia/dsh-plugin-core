## 背景

用户要一个「能直接用眼睛看」的预览页，不读文档。疑虑是：我们的样式机制依赖 DSH 运行时，
脱离宿主持不兼容。要求先看别人怎么做，别闭门造车；并明确要：明暗切换、中英切换、左侧分类导航。

## 待办

无。

## 下一步

等用户看完预览站提反馈（视觉常量大概率要调）。

## 过程

**先查证「脱离 DSH 能不能预览」——能，三条理由**：

1. 样式注入机制（`setStyleKit` + `ensureControls`）本质是 `document.createElement('style')`，
   **纯浏览器 API，不依赖宿主**。DSH 的特殊性只在「为什么必须这样做」，不在机制本身。
2. ui 已零 `@deepseek-ai/*` 依赖（质检时清零）。
3. 依赖宿主 API 的两个组件用 mock 数据（`demo/mock.ts`：假目录树 / 假会话）。

⇒ 预览站与真实插件走**同一条渲染路径、同一份 CSS 字符串**，效果一致。

**信息架构照主流组件库文档站**（查证 antd / Arco / Radix / MUI 后确认是同一模式，未自创）：

- 左侧分类导航（组件按功能分组）
- 主内容每个 demo = 实时渲染 + 用法代码（API 表已在 `docs/`，不重复）
- 右上角明暗 / 中英切换
- SPA 单页

**实现**：`demo/`（Vite + React，devDep 加 vite / @vitejs/plugin-react / react-dom，不影响发布物）

```
demo/
├── index.html        骨架（含预览页自己的 body 明暗变量）
├── main.tsx          入口：setStyleKit + ensureControls + createRoot
├── App.tsx           布局：左侧导航 + 右上角明暗/中英 + 主内容
├── mock.ts           假 workspaceFiles / 假 sessionSource
└── sections/         8 个分类：design / buttons / pickers / feedback /
                      display / utils / explorer / session
```

**明暗切换的做法值得记**：切 `document.body` 的 `data-ds-dark-theme` 属性 —— 这正是宿主的判定方式，
所以预览页**连明暗逻辑都跟真实环境一致**（不是另做一套）。也支持 `?theme=dark` 直接进暗色。
