## 背景

起因不是“CSS 想换个写法”，是 2026-10-19 那一整天的事故复盘。

事故本体（`20261019-1604-…-823a` / 提交 `dbfbccf`）：`src/design/tokens-css.ts` 的模板字符串
结尾多写一个反斜杠（`\`` 而非 `` ` ``），字符串内容因此多出字面反引号，落在 tokens 与控件
样式的交界处；CSS 解析器把它当不合格选择器开头，一路吞到下一个 `{` ⇒ 紧随其后的
`.dshpc-seg` 的**整个选择器**被污染成匹配不到元素的怪选择器。规则仍在 CSSOM、不报错、
不告警，只是永不生效 ⇒ `display:inline-flex` 从未落地、轨道退化成 block。

该 bug 已修复（`dbfbccf`），但用户不接“把这一个洞堵上”这个交付：

- 原话精神：**不是要改动最小，是要最健壮**；要最成熟、最正规、最容易维护的架构。
- 担心的不是这次，是“我不会预知下一次”——手工拼字符串的写法保留了整类失败模式的入口，
  今天堵反引号，明天还可能是别的字符/别的转义。不接受“遇到一个耗一天”。

所以本任务是**架构改造**：消除“CSS 以手工 TS 模板字符串承载”这个失败模式类别，而不是修 bug。

真源与约束：

- 宿主到底 complaining 什么：`docs/design/external/dsh-host.md` §1 / §1.1 —— 插件产物是
  `window.__ModuleLoader__.load` 的 CJS 闭包，**内核不加载任何 css 资源**，`import './x.css'`
  出来的文件没人用 ⇒ 运行时形态**必须**是字符串注入。这条不能动。
- 但它只约束“产物”，不约束“源码”：源码完全可以写真的 `.css` 文件，构建期转成字符串。

**② 实测 B（bundle）的产物形态代价**

```
dist/ui 现有文件数: 128
bundle 后单入口产物数: 1（119186 bytes）
```
⇒ `dist/ui/controls-css.js` 这类内部模块**不再存在**。

**③ 构建链审查（独立 agent，只读）** —— 挖出两笔我之前没算到的损失：

- `src/ui/official.ts` 与 `src/ui/ticker.ts` **不在** `src/ui/index.ts:4-27` 的导出表里。tsc 下
  它们照样被编译发出；esbuild bundle 会当不可达模块**静默丢弃**。而 `AGENTS.md:23` 定的是
  「`ui` 必须零 `@deepseek-ai/*` 依赖」，`official.ts:19` 恰恰引用了官方 primitives。
  ⇒ bundle 会把一条**显式违规从「有产物可查」变成「看不见」**。
- `package.json:20` 是 `"sideEffects": false` + 6 个细粒度入口，消费方能 tree-shaking。
  bundle 后 `dist/ui/index.js` 是固化全量（21 控件 + 28 KB 控件样式 + 19 KB tokens），
  **只 import 一个 `Button` 也要背约 90 KB**，且消费方无从优化。要修只能开 `splitting`，
  代价是哈希 chunk 名 —— dist diff 再恶化一档。
- 另有 12 条自检会红：`test/css-contract.test.mjs:9-18,140`（9 条）+ `test/ui.test.mjs:3`（3 条），
  全部依赖「dist 保留模块边界」。

**④ 维护性审查（独立 agent，只读）** —— 指出 A+ **自己**的新失败模式，必须配闸：

- 链路从一跳变四跳：`.css → *.generated.ts → dist/*.js → test`，任一跳脱节都静默：
  · 生成物被手改 → 下次生成被悄悄覆盖
  · 改完 `.css` 忘了重新生成 → 测的还是旧产物
  · 生成器转义策略写错 → 换一个新的单点
  · 每次改样式出两份 diff → review 分裂
- **铁律**：本次事故的位置是**拼接交界**（`dsh-host.md:83-85`）。任何「只对单个文件校验」的改造
  都会把这条防线拆掉 ⇒ 必须保留对最终拼接文本的整体解析 + 反证用例。

### 为什么不照抄官方

官方 `?inline`（`deepseek-harness/packages/client/tsdown.client.ts`，配合 `lightningcss` + 虚拟
模块 `\0dsh-css:`）能成立，是因为他们有整套基础设施：tsdown 打包器、lightningcss 转换、
CSS Module 类名哈希、同一个 `.css` 要同时服务「哈希类名导出」和「inline 字符串」两种用法。

我们只有「字符串」这一种用法。照抄用法而不带基础设施，得到的是一个**不完整的版本**：唯一收益
（真 `.css` 文件）A+ 同样有，而 dist 不可审、12 条测试断、tree-shaking 归零这些代价是白背的。

## 结论

- **方案排序（三个来源一致）：A+ > 现状 > B。**
- **已选定 A+**：真 `.css` 文件 + 构建期 lightningcss 校验 + `JSON.stringify` 生成 TS 字符串
  （生成物入库）+ tsc 照旧 1:1 出 JS/d.ts。dist 形态、exports、消费方 tree-shaking、现有测试
  全部零损失。
- **A+ 要成立，三条硬性配套缺一条就退化（不如现状）**：
  1. 幂等闸 `gen && git diff --exit-code`
  2. 保留对**最终拼接文本**的整体解析 + 事故反证用例
  3. 生成物用 `JSON.stringify` 产出，永不手写模板字符串（本次事故的成因而这条被物理删除）
- **顺带发现现状的一个独立缺口**（与选型无关，必须补）：`test/*.test.mjs` 从 `dist/` 导入，
  不先 build 就 `pnpm test` 等于测旧产物 ⇒ 加 `pretest`。
- **留的坑**：手工书写 HTML/CSS 字符串回归的根源是「没有编译器把关」，A+ 把把关提到了构建期，
  但生成器自身成为新的单点，靠它的转义用例覆盖。
