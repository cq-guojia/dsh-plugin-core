## 过程

**打包硬约束**（源自 dispatch 表 README:115、tsdown.client.config.ts:19-58、src/client/ui/style.ts:1-27）：

- 宿主以 git/npm 装插件**不跑构建脚本** ⇒ 包必须发预编译 dist，不能指望消费方 build。
- client 产物是 `window.__ModuleLoader__.load({ id, factory })` 的 CJS 闭包，`import './x.css'`
  只会产出独立 css 资源、**内核不加载** ⇒ 样式只能以 TS 字符串 + 运行时注入分发。
- `react` / react-dom / `@deepseek-ai/*` primitives 走 PLATFORM_MODULES 白名单保留 `require()`；
  打进包里会产生第二份 React 实例（hooks 直接崩）⇒ 一律 optional peer + external。

**包形态裁决**：`dsh-plugin-core` 一个 npm 包 + 子路径导出 `./ui`、`./files`（重入口 `./files/codemirror`）。
曾考虑拆多包，结论是 tree-shaking 让拆包在产物大小上零收益，只多出双 tag / 发布顺序 / 跨包 peer 区间
的协调成本；规模变大到依赖区间互相打架、或 files 因宿主 API 频繁 breaking 时再拆（files 是头号候选）。
用户确认的模型：**安装 = 整包；使用 = 按子路径 tree-shaking**。

**边界（四方调研共识）**：

- 进：token 映射表（前缀参数化）、注入器工厂、基础控件（Segmented / Button / Input 家族 / Textarea /
  Checkbox / MarqueeText / Loading / SectionHead / BackToTop / LiveText / resizer）、日期时间、
  文件浏览、HTTP client 骨架、i18n 基建、宿主类型面 + 能力探测、官方 CSS-module 类名发现。
- 不进：`mirror/` 官方会话 UI 全家（`ui-style-guide.md:108,110` 已判定「不抽」，宿主升级三插件集体漂移）、
  业务 token（`--tdt-cal-*` / chip-bg / filechip / PROCESS_FILES_CSS）、TaskPicker、CodeViewer 审美、
  `PANEL_CONTENT_ID` 页面几何、任何插件私有路由 / DB 表、`@deepseek-ai/*` 运行时依赖。

**现状（重复真实存在，非臆造）**：token 层已有三份平行副本（`--tdt-` dispatch 表 / `--dtl-` task-ledger
逐行复制 / `--stp-` session-title-pattern），注入器三份，且审美已分叉（输入框 34px+layer-3 vs 32px+layer-1）。
⇒ 头两个消费者：`dsh-task-dispatch-table`（删自有副本）、`dsh-task-ledger`（删 `tokens.ts` / `ui.ts`）。

**发布方式**：npm 公开包。私有包会让最终用户装插件时要配 token（GitHub Packages 上次就是因此被否），
且 npm 私有需付费；**公开 ≠ 开源**——发布物只是 `files` 指定的 dist，源码仓可以私有。OIDC 发布复刻现有
三个仓的 workflow 即可。

**命名**：`dsh-plugin-base` / `dsh-plugin-kit` 已被占；`dsh-plugin-core` 空闲，用户拍板。
