## 背景

需求文档 §2.3 + Q1 结论：公用方法独立成 `./utils`，UI 保持纯粹。
**硬约束**：utils 不得 import 任何其他子包、不得依赖 React / DOM / 宿主 API，
只能用标准库 + 注入的参数（为了让用户将来能把 utils 整体剥出去复用）。

无。

## 过程

**搬了什么**（源：`dsh-task-dispatch-table/src/client/format.ts` 与 `time-text.ts`）：

- `date.ts`：`pad2` / `formatDateTime` / `formatYmd` / `formatClock` / `formatDurationHms` /
  `sameCalendarDay` / `relativePast` / `formatRange`（区间）/ `overlaps`
- `string.ts`：`baseNameOf`（含**尾斜杠先剔**的修正，否则目录取末段成空串）/ `truncateBytes` / `safeTrim`
- `number.ts`：`formatBytes` / `formatCount`
- `http.ts`：`request` / `requestJson` / `HttpError`

**没搬**：`formatTokenCount` / `formatTokenDetail` / `formatPlanStamp` —— 业务味重（token 计数、
计划列口径），不满足「任何 DSH 插件都要用」的判据。

**多语言（Q2 落地）**：`relativePast` 这类会吐文案的函数 ⇒ **核心提供的就核心负责**，
所以 utils 自带中英字典（`i18n.ts`：`setLocale` / `getLocale` / `t`），同时保留**传 `t` 覆盖**的口子。
插件自己界面的文案仍不归 utils 管。

**HTTP 骨架的两个决定**：
- 超时用 `AbortController` + `setTimeout`，**不用 `AbortSignal.timeout`** —— 后者要 Chrome 103+，
  而宿主目标内核是 chrome99。
- 非 2xx / 网络失败 / 超时**一律抛 `HttpError`**（`status: 0` = 没拿到响应），不返回 null，
  逼调用方处理而不是漏判。

**踩坑（测试自己写错）**：`truncateBytes('abcdef', 3)` 我期望 `'ab…'`，实际 `'…'` ——
`…` 本身占 3 字节，3 字节预算只够放省略号。是**断言写错**不是实现错，改断言为 `(…, 5) → 'ab…'`。

**依赖纯净性**：加了 grep 检查（utils 源码里除相对导入外无任何 import），确认纯净。

## 结论

`dsh-plugin-core/utils` 可用，7 组自检全过，依赖方向干净（不碰 design / ui / React / DOM / 宿主）。

留坑：
- `formatRange` 的跨天格式（`03-05 09:00 – 03-06 10:30`）是我定的，**没有第二家验证过**，
  三家现有代码里没有对应实现可对拍。
- `http.ts` 真跑网络的部分（超时、非 2xx）**没测**（测试里没起服务），只保证类型与代码路径正确。
- 本机时区是沿用三家口径的既有约定，没改成 UTC —— 若将来有插件要跨时区展示，得另开任务加参数。
