## 背景

**现象**：demo 的会话预览弹窗（`SessionViewModal`）里点文件链接 → 核心 `openFilePreview` 在页面右侧开出 dock（主区确实被挤窄了），但 dock **被弹窗遮罩盖住**：压暗 + 点不动。

**用户原话（2026-10-22）**：「它的侧边栏有问题，被弹窗的遮罩给挡住了……侧边栏应该完全模拟，完完整整地开一个，就像一个页面被推出来一样。不管页面上有没有弹窗，都要把整个左边的内容完全往左挤。」

**上一轮的错误做法（待撤回）**：给 `Modal` 加了 `mask` / `maskInsetRight` 两个 prop，让**调用方**（demo）用 `ResizeObserver` 量 dock 宽度再传进去。用户判定这就是「把核心该管的事推给内容去调」，且实测不生效（见「过程」）。这两个 prop 是**待删的补丁**，不是本任务的方案。

**判定结论**：这是核心的两处缺失，不是 demo、也不是会话预览组件的问题（详见「结论」）。

## 过程

**兄弟项目的真源做法（不是 z-index）**：

- `dsh-task-dispatch-table/src/client/archive-session-css.ts:21`：`.dsh-tdt-sv-overlay{position:fixed;top:0;left:0;bottom:0;right:calc(var(--dsh-tdt-preview-w,0px) + var(--dsh-tdt-editor-w,0px));…}` —— 遮罩（含弹窗）右边界**减掉 dock 宽度**，永远停在 dock 左缘。
- `dsh-task-dispatch-table/src/client/index.ts:1156,1163-1165`：根容器是横向 flex（内容区 `flex:1` + 右侧各 dock 各占一份），dock 是**布局成员**、宽度写在 CSS 变量，拖拽期只改变量/元素宽度，避免整页重排。
- 同文件 `archive-session-css.ts:26` 明确「dock 是 sticky 布局成员、不是浮层，**不设 z-index**」。

**本仓现状（缺口）**：

- `src/ui/feedback.css:3-6`：遮罩写死 `inset:0` —— 必然盖满视口，这是根因。
- `src/ui/PanelDock.ts:352` 面板宽度只写成行内 `style.width`，`:273` 拖拽期直接改元素宽度；**没有任何对外宽度通道**（`onResize` 只在松手后回调单栏宽度，拿不到「总宽度 / 实时值」）。
- `src/explorer/open.ts` 头部注释已明确 dock 是布局成员、`mount` 传调用方的 flex 行 —— 布局这一半是对的，缺的是「发布宽度」。

**为什么调用方量宽度的补丁不生效**（实测结论）：

1. `openFilePreview` 用 `createRoot().render` 挂载，**异步**；demo 的 `ResizeObserver` effect 在 `pageRow.querySelector('.dshpc-dock')` 里拿不到节点 ⇒ `dockWidth` 保持 0 ⇒ `insetRight` 为 `undefined` ⇒ 遮罩仍是全屏。
2. 即便量到，`mask={false}` 只把遮罩透明化；弹窗面板本身仍是视口居中、宽 1120，会压住 dock 一角。
3. 本质错误：**内容侧决定遮罩几何**，与「滚动该归核心」是同一类越界。

**也不要走 z-index**：给 dock 提 `z-index` 压过遮罩 1070，会反过来「弹窗被 dock 盖住」+ 两套点击区域互相打架，与兄弟项目的显式约定相反。

**2026-10-22 复核方案时补的两点（原方案漏了）**：

1. **只让遮罩让位不够** —— `Modal.ts` 的 size 宽高按 `100vw` 算（lg = `min(1120px, 100vw-32px)`）。遮罩让位后可用区 = 视口 − dock，但宽度仍按视口取：1440 视口 + 460 dock ⇒ 可用 980、弹窗 1120，左右各溢出 70px 压到 dock 上，等于白让。改法把 `100vw` 换成 `100%`（相对遮罩盒），比「再减一个变量」简单且宽高口径统一。
2. **必须支持多 dock 求和** —— demo 自己就有两个 `PanelDock`（`client/index.tsx:137` 整页 demoDock + `open.ts:136` 预览 dock）。各写各的同一个变量 ⇒ 后写者覆盖；关掉一个又清 0，另一个还开着的 dock 被遮罩盖回。落地为模块级 `Map<实例键, 宽度>` 求和，不发导出。

**落地（全部完成）**：

**真机第二轮（2026-10-22，用户报「关掉 dock 后遮罩不回弹」）**：

现象：dock 关了、页面也回弹了，遮罩却停在原来的让位位置，一直不回全屏。判定是**占宽的登记没人回收**，两条成因一起修：

1. **根因（真机可复现的路）**：`openFilePreview` 重复打开时写的是 `previous.remove()`（`open.ts:96` 原代码）——直接摘掉挂载体，**跳过 React 根的卸载清理**。点第二个文件链接就会留下一个「已死但没注销」的宽度登记，此后关掉新 dock 时总和里仍有这份残留 ⇒ 遮罩永久卡住（页面回弹是因为 DOM 真被摘了）。改为模块级 `activePreviewClose`：重复打开走 `close()`（真正 unmount），`close()` 里再判断是否是自己那份。副作用：泄漏的 React 根、FileBrowser 的 RPC 订阅也一并收掉了。
2. **再加一道兜底**：`dockInsets` 的条目改存 `{ width, el }`，`publishInset` 每次先把「元素已不在文档里」的条目摘掉。这样就算将来又有人绕过 `close` 直接 remove 挂载体，下一次任何 dock 发布时也会自愈，不至于永久卡住。

回归测试：`test/explorer.test.mjs` 加一条，钉死「重复打开必须先卸载旧根、不许直接 remove 挂载体」。验证重跑：build / typecheck / build:demo / test（**92** tests）全绿，`koc-codelint` 仍只剩那 5 条历史告警。

## 结论

- **是核心的问题，且是核心两处**：① `Modal` 遮罩几何写死全屏；② `PanelDock` 不对外发布自身占宽。修好后 `SessionViewModal`（会话预览）**不需要任何遮罩相关参数**，demo 也不需要测量。
- 契约最终落地 = 根元素 CSS 变量 `--dshpc-page-inset-right`（挂点 A），PanelDock 写、遮罩读，多 dock 求和、关闭即移除。`mask` / `maskInsetRight` 已删（只是上个 commit 的临时补丁，全 `/code/dsh-plugins` 只有本仓 demo 用过）。
- 已知限制（没改、也无法从核心修）：宿主 `confirmModal({skin:'host'})` 走官方 Modal，遮罩几何不归本仓管，分栏在场时仍会盖住 dock。
- 「关掉 dock 后遮罩不回弹」已定位并修掉：`openFilePreview` 重复打开时直接 `remove()` 挂载体 ⇒ 旧 React 根的卸载清理被跳过 ⇒ 占宽登记永久残留。现在改走 `close()`，并给登记表加了「元素已离开文档即丢弃」的兜底。
- 代码已改完待真机二次验收；提交由用户明确说「提交」再走。
