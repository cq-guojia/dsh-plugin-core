## 背景

上一个任务（`20261018-0414` ui 基础零件）里我让 `buildCss()` **同时替换两处前缀**：
变量 `--tdt-` 和类名 `dsh-tdt-`，理由是「不换类名的话两个插件的 `.dsh-tdt-btn` 会互相覆盖」。

**这是错的**：控件是从兄弟仓搬来的，里面的 className 是**硬编码字面量**
（`className: 'dsh-tdt-btn'`、`` `dsh-tdt-btn dsh-tdt-btn--${size}` `` 等）。
只在 CSS 侧把类名换成 `dsh-acme-btn`，组件的 className 仍是 `dsh-tdt-btn`
⇒ **选择器与 className 对不上，控件样式整片失效**。

上一个任务没发现，是因为**只在无 DOM 环境测了字符串替换，没在浏览器里渲染验证过**
（它的「留坑」里写了这条，本任务就是这个坑落地）。

## 待办

无（已修）。

## 过程

修法：`buildCss()` **只换变量前缀 `--tdt-`，类名 `dsh-tdt-` 原样保留**，
并把这个决定与理由写进函数注释（避免以后有人又"顺手"把类名也换掉）。

为什么选「保留类名」而不是「连组件的 className 一起改」：

- 改 className 要对 14 个控件里所有字符串/模板字符串做替换，漏一处就是该控件样式全丢，
  而当前**没有渲染验证手段**（没有浏览器 / 没装 react 渲染测试），漏了也发现不了。
- 收益是防「两个插件引不同版本 core 时 `.dsh-tdt-*` 规则互相覆盖」—— 同版本时内容一致、无害，
  属边缘情况。
- 主防线仍在：style 标签 id 隔离（`createStyleKit({ id })`）+ 变量前缀隔离。

**已知限制（写进注释了）**：两个插件若引的 core 版本不同，`.dsh-tdt-*` 规则会互相覆盖。
真要彻底隔离，另开任务：给每个控件加 `cls()` 生成类名，同步改 CSS 与组件两侧。

测试同步改：断言从「类名必须换掉」改成「类名必须保留 + 变量必须换掉」，把这个 bug 钉住。
