## 过程

**搬法**：写脚本批量搬运 + 机械替换（不手工转录，避免 26KB CSS 与 13 个控件抄错）：

- CSS：从 `controls-css.ts` / `loading-css.ts` / `back-to-top-css.ts` 提取 7 个 CSS 块
  （SEGMENTED / BUTTON / FIELD / DATETIME / SELECT / LOADING / BACK_TO_TOP），
  **排除 `PROCESS_FILES_CSS`**（业务件，需求 §3 不进）。
- 控件：Button / IconButton / Segmented / Textarea / Checkbox / MarqueeText / Loading / RunningBlocks /
  SectionHead / LiveText / BackToTop / resizer / ticker / Field（Input / PrefixedInput / NumberInput /
  SelectField / fieldMetricsOf）。源文件是 `createElement as h` 写法、无 JSX ⇒ `.tsx` 可直接当 `.ts` 用。
- 机械替换：相对导入补 `.js`；所有 `ensureXxxStyle()` / `ensureUiBase()` 统一成 `ensureControls()`。

**关键设计：当前 kit 用「模块级变量」而不是 React Context。**

理由：core 会被**内联进每个插件各自的 bundle**（不是共享运行时），所以模块级变量天然按插件隔离，
不像共享模块那样会互相踩。用法：插件启动 `setStyleKit(createStyleKit({ id, prefix }))` + `ensureControls()` 一次。
比 Context 改动小得多（不用给每个组件插 hook）。

**前缀要换两处**：不只是变量 `--tdt-`，**类名 `dsh-tdt-` 也要换** ——
只换变量的话两个插件的 `.dsh-tdt-btn` 规则会落在同一个类名上互相覆盖。`buildCss()` 一次换两个。

**踩坑（都是脚本搬运引来的，会复现）**：

1. 插入 `import { ensureControls }` 时用 `indexOf('import ')` 定位，**Textarea 的注释里正好有
   "import" 字样** ⇒ import 被插进注释中间，把后面的代码也吞进注释。改成按真实 import 行定位。
2. 清理残留 import 的正则 `[^}]*` 会**跨行匹配**，误删了 `css.ts` 的多行 import（发现后补回）。
3. 官方 primitives 用短声明 `declare module 'x'` 时，`MenuEntry` 只能当值、**不能当类型**
   （`Field.ts:274` 报 TS2709）⇒ 改成完整模块声明，符号全按 `any` 放行。
4. `resizer.ts` 有个取了没用的 `startX`（源仓就未使用），`noUnusedLocals` 下报错 ⇒ 删。

## 结论

`dsh-plugin-core/ui` 基础层可用：14 个控件 + 7 块 CSS，编译干净，4 条自检全过
（双前缀替换 / set-get kit / 无 DOM 不抛 / 默认 kit 兜底）。

留坑（重要）：
- **没有在浏览器里渲染验证过** —— 只保证编译与样式字符串正确。控件真实外观要等消费者接入一起验。
- `SelectField` 依赖官方 `Menu`（primitives），**运行时行为未验**；本包只给了最小 any 声明。
- 反馈件（Modal / toast / 空态 / 错误边界）与选择器（Picker / ModelPicker）**还没做**，后续任务补。
- 没装 `react` 到 devDependencies（测试绕开了控件渲染，只测 css 层）。
