### 二、参数完备性（按「消费方会怎么用」逐项推）

**判断方法**：把每个导出组件/函数当成「明天有个不认识我的插件作者来用」，他会想干什么、
会卡在哪。结论：**原来缺的参数集中在 Picker / Modal 两个零件上**。

**Picker**（补 9 项）

| 缺的参数 | 消费方场景 | 状态 |
|---|---|---|
| `clearable` | 单选场景经常要「不选」（如模型跟随宿主可清空） | ✅ |
| `defaultValue` | 非受控用法：小场景不想自己管 state | ✅ |
| `size` (`sm`/`md`/`lg`) | 与其他控件（Field）尺寸档不一致，混排难看 | ✅ |
| `className` | 要定制宽度 / 外边距 | ✅ |
| `placement` (`down`/`up`) | 触发器在页面底部时菜单被视口裁掉 | ✅ |
| `closeOnSelect` | 多选连续选时不想每选一次就收起 | ✅ |
| `showLabels` | 多选想在触发器上看清选了谁，而不只是「已选 3 项」 | ✅ |
| 键盘可达（Esc / ↑↓ / Enter） | 键盘用户与无障碍 | ✅（最小版，非完整 aria 树） |
| `ariaLabel` / `aria-expanded` | 读屏软件 | ✅ |

**Modal**（补 4 项）：`closeOnMask`（误触代价大的场景要关掉点遮罩关闭）、
`escClose`（默认开）、`maxWidth`（窄内容场景）、`hideHeader`（沉浸式）。

**ModelPicker / WorkspacePicker / FilePicker**：上述参数全部透传（原来各自只暴露一小半）。

**StyleKit**：补 `dispose()` —— 插件卸载 / HMR 时样式标签会残留，原来没有任何清理手段。

**utils/date**：`formatYmd` / `formatClock` 补 `opts.fallback`（原来兜底写死）；
**新增 `relativeFuture`** —— 只有 `relativePast`，而调度表这类插件展示的是**未来**时间，
用 `relativePast` 会把「3 分钟后」显示成「刚刚」，直接丢语义。

**ExplorerPanel**：补 `onSelect`（选中状态外部不可感知，调用方没法联动）、
`emptyText`（空目录文案不可覆盖）。

### 四、未修项（重要，别以为质检完就全好了）

1. **全包零渲染测试** —— 33 条自检全是逻辑层/字符串层，**浏览器里的真实外观、注入器挂载、
   控件交互一条都没验**。这是最大风险，质检再怎么查也补不上。
2. **CSS 类名未跨版本隔离**（同版本无害，两个插件引不同 core 版本会互相覆盖）。
3. **`mirror/` 官方会话 UI 镜像未搬**，会话预览仍是最简渲染。
4. **文件预览无代码高亮 / 不支持 PDF 与 Office**。
5. **无 props 文档表**（每个组件的参数、默认值、示例）。
6. **无障碍只做了最小键盘支持**，没有完整 aria 树 / 焦点管理。
7. **`Picker` 多选上限提示用的是降级样式条**，视觉上与「候选不完整」提示同款，
   语义上其实是两回事（上限是用户行为、降级是数据状态）⇒ 建议后续拆开。
