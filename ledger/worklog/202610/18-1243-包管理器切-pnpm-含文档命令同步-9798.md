**⚠ 顺带修掉一个真 bug**：`pnpm add` 第一次直接失败：

```
ERR_PNPM_NO_MATCHING_VERSION
No matching version found for @deepseek-ai/dsh-client-ui-primitives@>=0.1.0
The latest release of @deepseek-ai/dsh-client-ui-primitives is "0.0.1-rc.1"
```

- `peerDependencies` 里那条 `@deepseek-ai/dsh-client-ui-primitives: ">=0.1.0"` **范围写错**
  （latest 是 `0.0.1-rc.1`，`>=0.1.0` 解析不到）。
- **npm 一直侥幸放过**（装 devDependency 时没触发对该 peer 的解析），pnpm 严格解析才暴露。
- 更关键：质检时我们已把 `ui` 的官方依赖全删了（BackToTop 自绘、SelectField 删除），
  `src/` 下**已无任何 `@deepseek-ai/*` import**（只剩 `src/types/primitives.d.ts` 一条没人用的声明，
  本次一并删掉）⇒ 这条 peer 是**过时残留**，直接删。
- 留下的 peer 只有 `react` / `react-dom`（均标 optional）。

**⚠ 一个环境相关的发现：ZFS 上 pnpm 默认的 reflink 没生效**

第一次 `pnpm install` 后 `node_modules` 是 **58M**，而 npm 时代只有 **25M**——反而更大。
排查：`/code` 与 `/opt/node-persist` 同在 `zfsv3`（ZFS），pnpm 12 在支持 CoW 的文件系统上
默认走 **reflink**，但这个容器里 reflink 没生效、退化成 copy；叠加 pnpm 的 peer 隔离结构
（每个包的私有 `node_modules` 各存一份公共依赖），体积就翻上去了。

处置：`.npmrc` 加一行 `package-import-method=hardlink` 强制硬链接，重装后 **33M**
（追平 npm 的 25M，多出的 8M 是 `.pnpm` 目录结构与符号链接）。

**给推广决策的实测数据**（另两个仓切不切看这个）：

| | npm | pnpm（默认） | pnpm（hardlink） |
|---|---|---|---|

⇒ **推广到 dispatch / ledger 前必须先加 `.npmrc` 那行**，否则体积可能不降反升
（dispatch 101M 有翻倍风险）。`.npmrc` 建议随推广一起带上。

留坑：
- ZFS 上为何 reflink 失败没深究（容器/驱动层面），hardlink 是绕开不是修复。
- 删掉的 `@deepseek-ai/*` peer 意味着：**若将来某个子包真的要 import 官方包，得把 peer 加回来**
（并先确认版本范围能解析——这次的教训）。
