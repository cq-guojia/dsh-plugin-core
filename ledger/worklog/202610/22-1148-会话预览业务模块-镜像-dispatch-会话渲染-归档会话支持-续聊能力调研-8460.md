### 三、归档会话支持（用户第二点）——调研结论

源码级事实（兄弟项目 `docs/design/external/dsh-capabilities.md`，适用 0.1.7-rc.1~0.2.0-rc.2）：

- `archiveSession(id)` 只把 id 加进 `archivedSessionIds`（**显示面隐藏名单**），不动 `sessionIds` 槽位；`session/list` 不过滤归档 ⇒ **归档会话「可读、不可从 UI 打开」**（dsh-capabilities.md:32）。
- `sessions.binding(id)` = `this.scopes.get(id)?.binding`，**只查已物化 scope、从不创建**（api-session-controller 0.1.7-rc.2 lib/client.js:3406）⇒ 归档 / 久未打开的会话返回 undefined；`uiConversation.binding` 随即抛 `inactive session`（ui-conversation client.js:3083）。
- **正解**：`sessions.retain(id, { source })` → `retainScope`（3409）→ `materializeScope`（3472）物化 scope 并内部触发 `manager.get(id).open()` 拉历史尾页；用完 `release()`。**与归档正交**——retain 路径对归档会话同样有效（会话日志仍在）（dsh-capabilities.md:26）。
- 冷读 `session/follow` / `session/page`（durable address，归档可读）在类型契约里存在，但兄弟项目实测宿主 remote 只有 `$stream`/`invoke`、invoke 报「无活动通道」⇒ 探测默认关闭，**不作为依赖**。

⇒ **结论：本项目移植 retain 数据链后，归档会话预览天然获得，无需额外开发**。兄弟项目「任务跑完归档 → 记录时间线查看会话」就是这条主路径的日常形态。需在文档与测试中显式覆盖（假 binding 走 retain→binding→target 全链）。

### 四、「在会话框里继续聊」（用户第三点）——调研结论：底层数组不提供该能力

- 底层数组 = ChatSnapshot 的 `order` + `nodes`（ChatNodeStore）+ `timeline.turns`。三者在官方契约里全是**只读快照**（`SnapshotFace { getSnapshot, subscribe }`，session-view.ts:60-64 复述）；store 面只有 `get` + `processSource`，**没有 append / send / emit 任何写面**。
- `uiConversation.binding(binding).target('chat')` 返回的就是快照；官方没有「向预览 binding 发消息」的契约。发消息的唯一官方路径是 `ctx.agents.create({ sessionId })` + `agent.send(msg, 'next-turn', true)`——那是**唤醒 agent 驱动模型**，等于激活会话，不是「在预览框里打字」，且与「归档 = 留档不可改」语义冲突（兄弟项目决策 37）。
- 三条已证伪的路（兄弟项目真机实测，勿再试）：① 弹窗内挂官方 ChatView（`ctx.slots.renderSlot` 运行时只认 `key='root'`）；② 自己 `retain('mainView')` 切官方视图（**锁死宿主会话导航，真机事故已回退**）；③ 冷读 RPC `$stream('session/follow')`（宿主无活动通道）。
- **官方认可的路** = `sessions.fork({ sessionId, atSeq?, increaseTitle: true })` → 子会话 id → `uiWorkspace.openSession(childId)`（官方导航服务，内部自己 retain('mainView') + selection.set + selectPanel(null)，调用方只调服务、不碰保留值）。兄弟项目 U10 已实现：头部「继续对话」按钮 + 消息行分支 icon（从该轮 tail 截断），均走确认框防误点，先关弹窗 release 再跳转。

⇒ **结论：底层数组是只读投影，「框内续聊」无官方能力可调；按用户「不走歪门邪道」的要求，落点 = 移植 fork + openSession 的「继续对话（开分支）」**。若用户坚持框内打字续聊，需另立调研（agent.send 激活路），并接受「激活归档会话、与只读预览混排有竞态」的代价——不建议。

### 六、续聊交互升级（2026-10-22 讨论追加）：弹窗暂存输入框 + 带话跳转

用户提出：弹窗底部放输入框 → 用户打字 → 点「确定」→ 跳官方会话界面，且**那句话已经带给大模型、模型已开跑**。逐段核实：

| 段 | 能力 | 归属 | 证据 |
|---|---|---|---|
| 弹窗输入框 | 自绘，零依赖 | 客户端，我们的 UI | 无官方约束 |
| fork + openSession 跳转 | `sessions.fork` / `uiWorkspace.openSession` | **客户端官方服务**（inject 清单已有 sessions / uiWorkspace） | dispatch package.json dsh.client.inject；session-view.ts:1241-1264 |
| 发话 + 起轮次 | `agents.create({ sessionId })` + `agent.send(msg, 'next-turn', true)` | **仅 host 侧** | dispatch src/dispatch.ts:519,627；capabilities.md:19。客户端 inject 清单无任何 agent 服务；官方输入框的发送是官方 UI 内部行为，DOM 捅之 = 歪门邪道（用户明禁） |
| client→host 传话 | remote 服务（dotted inject）是官方跨侧模式 | **新东西，三家均未用过，实现期第一验证项** | 官方自己的 remote.workspaceFiles / officeToPdf 即此模式；本仓需自注册 host 半侧服务面 |

**结论**：整个流程可以走通，无一处歪门邪道；唯一真增量 = 给我们插件加 client→host remote 通道 + host 半侧 `agents.create + agent.send`。provider/model 必须显式给（capabilities.md:120：缺省会报错），取宿主默认选择 `ctx.get('agentDefaultModel').currentSelection()`。

**UX 时序**：确定 → fork（瞬时拿 childId）→ host 发话入队 → openSession 跳官方视图 → 用户看到模型已在跑；弹窗按 U10 aliveRef 模式等 childId 落定再 release 关闭。

**归档/未归档分歧**：归档必须 fork（官方策略归档不进主视图，navigation.ts:287 clearArchivedCurrent）；未归档可直开原会话，但建议统一 fork——一条代码路径、避开与主视图官方输入框的发送竞态、「基于历史起新轮次」语义更干净。
