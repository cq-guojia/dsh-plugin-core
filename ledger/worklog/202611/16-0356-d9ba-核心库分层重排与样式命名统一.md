## Background

用户从「通知和后台执行是不是两条线、要不要分包」一路问到目录结构，最终拍板分层。原话结论：
**「UI 下面的这些东西，纯技术的放 runtime；任务是一个高级控件，一整套跟着它走；它借助通知的广播能力。」**

起因是 `src/ui/infra/task-notifications.ts` 一处 1640 行同时装着四件互不相干的东西：任务池（状态机 +
跨页同步 + 超时 + 按钮 ack）、通知广播、跨页通道、默认分组。`ui` 这个目录名承诺「有界面」，
但里面一半是没有界面的能力 —— 用户看不懂 `ui/infra` 到底是什么，这是本次重排的直接动因。

同时用户发现样式文件名不统一（`DateTimePicker.ts` 配 `datetime.css`），要求**旧的全部改统一，
不留历史包袱，并加闸防止再跑偏**。

## Process

**1. 任务不进 runtime。** 任务池带业务语义（项目 / 分组 / 业务键 / 状态机），是成品不是底座，
按既有判据落 `adv`。它借 `runtime/store` 记当前任务、借 `runtime/message` 广播收尾事件，
但 runtime 不认识「任务」。

**2. `channel` 这一层取消。** 曾计划拆出独立的 `channel.ts`，用户否掉：「它不就是任务用的吗」。
核查后确认道理成立 —— 跨页同步的「整份 + 序号 + 新页面补一份」是任务自己的策略，
通道只负责送一条数据。合并进 `runtime/message.ts`，少一层。
唯一硬约束：`ui/feedback/notify-bridge.ts` 也要用它，所以它不能放 `adv/tasks`（否则 ui → adv 反向依赖，
违反 `structure.md` 的依赖方向）。

**3. 测试里硬编码的产物路径（拆完必红，须同步改）：**

- `test/entry-isolation.test.mjs:46` —— `./ui/task-notifications` 探针
- `test/task-notifications.test.mjs:511` —— `new URL('../dist/ui/infra/task-notifications.js')`
- `test/task-bar.test.mjs:5-6` —— `dist/ui/display/TaskBar.js` 与 `task-bar-css.js`
- `test/css-contract.test.mjs:41` —— `dist/ui/display/task-bar-css.js`
- `test/notify-bridge.test.mjs:7-8`、`test/notify-broadcast.test.mjs:9-10` —— 经 `dist/ui/index.js` 取符号
- `test/ui-taxonomy.test.mjs:38-46` —— `src/ui/index.ts` 的每条 `from './x.js'` 必须命中 7 个类目录，
  TaskBar 迁出后那条导出必须删，否则报 stray

**4. 不能动的字符串。** `Symbol.for('dsh-plugin-core/task-notifications/v2')` 与
`TASK_NOTIFICATIONS_CHANNEL = 'dsh-plugin-core/task-notifications/v2'` 被
`test/multi-copy.test.mjs:31`、`test/notify-broadcast.test.mjs:568`、`test/notify-isolation.test.mjs:12`
逐字断言，且是跨 bundle 副本的 ABI —— 拆到 `runtime/message.ts` 后**原样保留**，只换文件位置。

**5. 命名冲突：`notify` 已被占用。** `ui/feedback/notify.ts` 是「提示」的发送 API（本页卡片 / 可选广播），
跨页那层不能也叫 notify，故叫 `message`。`notify` 这个名字在用户认知里指「提示」，不建议反过来改。

**6. 默认分组必须搬走。** `ui/feedback/notify.ts:19` 从任务模块取 `getDefaultTaskProject` 用于广播。
任务搬到 `adv/tasks` 后这就是 `ui → adv` 反向依赖，所以 `setDefaultTaskProject` / `getDefaultTaskProject`
跟 `runtime/message.ts` 走（它是发送消息的默认标签，不是任务数据）；函数名保留（改名属破坏性）。

**7. 样式命名（已落地）。** 规则：字体名 = 组件文件名转 kebab-case，常量 = 文件名转大写下划线 + `_CSS`。
四个偏离项已改：`datetime.css` → `date-time-picker.css`、`hint.css` → `field-hint.css`、
`marquee.css` → `marquee-text.css`、`flip.css` → `flip-text.css`；域名参数同步
（`ensureComponentStyles('datetime'|'hint'|'marquee'|'flip', …)` 各加全名）。
`test/css-naming.test.mjs` 带 WHITELIST（8 项共用底座 / 模块皮肤，每项写了理由），
MAP 是唯一真源，不另抄清单。
