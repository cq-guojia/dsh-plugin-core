## Background

用户从「通知和后台执行是不是两条线、要不要分包」一路问到目录结构，最终拍板分层。原话结论：
**「UI 下面的这些东西，纯技术的放 runtime；任务是一个高级控件，一整套跟着它走；它借助通知的广播能力。」**

起因是 `src/ui/infra/task-notifications.ts` 一处 1640 行同时装着四件互不相干的东西：任务池（状态机 +
跨页同步 + 超时 + 按钮 ack）、通知广播、跨页通道、默认分组。`ui` 这个目录名承诺「有界面」，
但里面一半是没有界面的能力 —— 用户看不懂 `ui/infra` 到底是什么，这是本次重排的直接动因。

同时用户发现样式文件名不统一（`DateTimePicker.ts` 配 `datetime.css`），要求**旧的全部改统一，
不留历史包袱，并加闸防止再跑偏**。

## Process

**1. 边界是按代码事实划的，不是按名字划的（评审结论）。**

原计划拆出独立的「纯传输」`message.ts`（含 seq 去重、hello/bye），评审证明这个边界是假的：

- 仓库里是**三套独立序号**：分片 `seq`（`:851`）、消息 `messageSeq`（`:855`）、调用 `invokeSeq`（`:857`）。
- 去重只发生在分片上（`:1143-1149`），而且是单向的：广播消息**完全不去重**（`:1124-1128`），
  invoke 靠 `reqId` 配对（`:1135-1141`）。
- 分片去重有一条只能读池的例外：分片已被删时接受同 seq 重发，判据是 `shards.has(origin)`（`:1146-1147`）。
- `hello` 必须回全量分片（`:1113-1115`）；`bye` 带 `seq` 并与 `knownSeq` 比较（`:1119`）；
  `invoke` 要查本页 runners（`:1129-1133`，表在 `:839`）。
- `connect()` 的重连补发依赖池自己的 `everConnected/everPublished`（`:1208-1217`）；`post` 在无通道时
  静默丢弃（`:897-899`），而 `ensure()` 是「先 connect 再 publish」（`:1247`）—— **时序本身是语义**。

所以「传输层」实际能干净搬走的只有 15 行（`openChannel` + `post`）。正确切法是：`runtime/notify.ts`
= **通知能力**（发/收/默认分组/事件总线），任务的整份同步、序号、握手全留在 `adv/tasks/pool.ts`。

**2. 命名回到 `notify`，不叫 `message`。** 两个 notify 靠目录和函数名区分：
`runtime/notify.ts` → `notifyMessage`；`ui/feedback/notify.ts` → `notify`。
（原写的是「`notifyMessage` / `notifyTask` 必须继续从 `ui/index.ts` 导出」，**已被推翻**：那会让
`ui → adv` 反向成环。最终由 `./adv/tasks` 与 `./runtime` 两个单块入口提供，`ui/index.ts` 一格不留；
`ui/feedback/notify.ts` 要的两个能力改从 `runtime/notify.js` 取。）

**3. 事件总线必须单一所有者。** `TASK_NOTIFICATIONS_EVENTS_KEY`（`:29`）是跨 bundle 的 `Symbol.for`
单例，`isEventBus` 只校验 `emit`/`subscribe` 是函数（`:569-576`）。若 runtime 与 adv 各建一个，
先到者占坑、后者静默拿到形状合法的错对象 —— 只在多插件同页时复现，且不报错。归 `runtime/notify.ts`。

**4. 默认分组必须搬走。** `ui/feedback/notify.ts:19` 从任务模块取 `getDefaultTaskProject` 用于广播；
任务搬去 `adv/tasks` 后就是 `ui → adv` 反向依赖。全量使用点只有 4 处（定义 `:351,360`、
`requireProject :413`、`notify.ts:19,109`、导出 `ui/index.ts:15`），返回 `string | undefined`，
不带记录类型，搬家干净。`TASK_NOTIFICATIONS_PROJECT_KEY` 字符串原样保留（ABI）。

**5. `RuntimeStore` 的规格是 4 个入参不是 3 个。** `useSyncExternalStore` 的第三参
`getServerSnapshot` 不能省：`TaskBar.ts:158-162` 传了它，`test/task-bar.test.mjs:15` 走
`renderToStaticMarkup`，SSR 时缺第三个参数直接抛错。另外池的 `subscribe`（`:1426-1429`）会顺手
`connect()`（开通道、抢存活锁、发 hello、重连补发，`:1199-1218`），那是任务的 bring-up，**不进容器**。

**6. adv 判据原写法过窄，已改。** 原判据是「必须拿到业务对象（工作区 / 会话 / 文件 / 模型）」，
而任务池一个都不认 —— 照原判据它根本不该进 `adv`，方案会给出「按规则不合格却按目录表放行」的先例。
改成「**是一整块功能（组件 + 能力一起交付、离开具体界面就不完整）**」，业务对象是常见特征、非必要条件。

**7. 发布入口是二选一，必须显式定。** `scripts/ui-entries.mjs:25` + `package.json:137-140` 把
`./ui/task-bar` 做成了已发布单块入口，`test/entry-surface.test.mjs:9-46` 双向校验。要留下这个子路径
就得在 `ui` 里留 shim 转 `adv` —— 那就是 ui → adv，违规。所以选**删**（breaking），并同步
`scripts/ui-entries.mjs`、`package.json`、`test/entry-surface.test.mjs`、`docs/api/ui.doc.ts:59,821`。

**8. 测试里硬编码的产物路径（拆完必红）：**

- `test/entry-isolation.test.mjs:46` —— `./ui/task-notifications` 探针
- `test/task-notifications.test.mjs:511` —— `../dist/ui/infra/task-notifications.js`
- `test/task-bar.test.mjs:5-6` —— `dist/ui/display/TaskBar.js` 与 `task-bar-css.js`

- `test/ui-taxonomy.test.mjs:38-46` —— `ui/index.ts` 每条 `from './x.js'` 必须命中 7 个类目录，
  TaskBar 那条导出必须删，否则报 stray

**9. 不能动的字符串。** `Symbol.for('dsh-plugin-core/task-notifications/v2')` 与

`test/notify-isolation.test.mjs:12` 逐字断言，且是跨 bundle 副本的 ABI —— 只换文件位置，不改值。

**10. 样式命名（已落地）。** 规则：文件名 = 组件文件名转 kebab-case，常量 = 文件名转大写下划线 + `_CSS`。
四个偏离项已改：`datetime.css` → `date-time-picker.css`、`hint.css` → `field-hint.css`、
`marquee.css` → `marquee-text.css`、`flip.css` → `flip-text.css`；`ensureComponentStyles`
的域参数同步改成全名。`test/css-naming.test.mjs` 带 WHITELIST（8 项共用底座 / 模块皮肤，逐项写理由），
MAP 是唯一真源不另抄清单，另带一条「WHITELIST 不许过期」的自检。

**11. `notifyMessage` 的标题改位置参数（已落地）。** 原来 `title` 混在入参对象里，`NotifyMessageInput`
把它标成必填，但调用方写 `notifyMessage({ level: 'error' })` 时错误只在类型层出现、读代码看不出「这是必填的」。
改成 `notifyMessage(title, options?)` 后必填语义由签名直说；接口随之改名 `NotifyMessageOptions` 并删掉 `title`。
定义只留 `runtime/notify.ts` 一处，`adv/tasks/pool.ts` 改为 `export type { NotifyMessageOptions }` 转发 ——
两份同名接口一定会漂移。连带改掉的调用点：`pool.ts` 的 `broadcast()`、`ui/feedback/notify.ts:115`、
`test/notify-bridge.test.mjs:28,37`、`test/notify-broadcast.test.mjs:27`（scope 打桩的函数签名）、
`test/task-notifications.test.mjs:893`。

**12. 入口面收敛后 `ui` 才不依赖 `adv`。** `ui/index.ts` 原来把任务 API 与 `TaskBar` 都从
`./infra/task-notifications.js` 转出；文件搬去 `adv/tasks` 后若继续转出就是 `ui → adv` 反向依赖
（structure.md §四 明令禁止）。做法是这两类导出整体删掉，改由 `./adv/tasks` 单块入口提供；
`ui/feedback/notify.ts` 需要的那两个能力（`notifyMessage` / `getDefaultTaskProject`）改从 `runtime/notify.js` 取。

**13. demo 页的代码块不另抄一份。** 新「运行时底座」页的示例代码直接 `DocCode({ id })` 读
`docData`（`docs/api/runtime.doc.ts` 的投影），页面里一个代码字符串都不写 —— 抄第二份就会出现
「文档改了页面没改」。另外默认项目从 `sections/task-notifications.tsx` 的模块级副作用挪到
`client/index.tsx` 的 `apply()`：那才是真正的 app 入口，也省得页面之间靠 import 顺序互相依赖。

**14. 用户截图点出的三处细节（已修）。**
- `TaskBar` 定宽 / 上限时，计数作为独立 `flex:none` 元素把三角挤出边框，且定宽时三角没有贴右。
  改成把「后台任务 + N 个运行中」拼成**一段**跑马灯文字，三角 `margin-left:auto` 钉右、触发器
  `overflow:hidden`。
- **僵尸任务**：`timeoutMs` 原来只靠下次写入前的惰性结算，没人再写就永远挂着。改成**单条定时器**
  守最早到期的本页任务，到点 `failed('timed out')` 并移出快照；每次写都按 `updatedAt` 重排（`update`
  / `background` 会续期），`dispose` 摘表、重连补排；写入前惰性结算留作后台标签节流兜底。
  踩坑两处：① 已经到点的条目在排程时必须排 1ms 后结算，不能跳过 —— 注册到 publish 之间过窗口
  就会永久漏掉；② **不能 `unref()`**（Node 里 unref 的定时器在空闲 loop 上不兑现，恰好是僵尸场景）。
  没有 finisher 的条目不排程，避免 1ms 空转。
- 自定义色实心按钮：暗色下 `--dshpc-fg-inverse` 变近黑，压在用户给的橙 / 蓝底上读不清。
  `colorVars` 给实心档的自定义 `color` / `background` 固定配 `--dshpc-on-signal`（两主题都白）；
  primary 自己的底色跟主题反色，不动。
- 对外展示名「通知任务中心」→「后台任务中心」（文档标题、demo 分组、代码注释）；API 名、
  文件路径、section id 都不动 —— 它用的确实是通知的底层能力，但不是「发一条就完」的通知。
