## Process

- 根因：`5717b7ff`（v0.35.18）把 width/minWidth/maxWidth 从 trigger 迁到 `.dshpc-picker` 根盒时只迁了 props，漏迁 trigger 基类自带的 `min-width:120px;max-width:100%`（`src/ui/inputs/picker.css:16`），两层各持一套宽度主张。旁证：hint 态 `picker.css:13` 已 `min-width:0`，从不犯。
- 否决「一行 `min-width:0`」：根盒是 `inline-block` 且 CSS 为 `min-width:0`（`picker.css:6`），shrink-to-fit 的下界正来自 trigger 的 120；直接压掉会让所有不传三轴的 Picker 缩到文字宽（`src/ui/navigation/Pagination.ts:171` 的 `minWidth:'auto'`、SplitGroup 内未定宽格全中）。
- 落地：`picker.css` trigger 改 `min-width:0` 并删 `max-width`；`picker-logic.ts` 导出 `PICKER_DEFAULT_MIN_WIDTH = 120`；`src/ui/inputs/Picker.ts:92` 用 `{ ...sizing, minWidth: sizing.minWidth ?? PICKER_DEFAULT_MIN_WIDTH }` 把默认下限放进根盒内联层（键顺序不变，兼容 `test/model-picker.test.mjs` 既有断言）；`Pagination.ts` 删掉 `minWidth:'auto'`；`src/ui/index.ts` 导出常量。搜索框仍走 `resolveTriggerSizing`，未改。
- 文档：`docs/help/ui.doc.ts` 的 Picker prose（中英）与 `minWidth` API 行写明「根盒唯一持有、显式值小于默认也生效」，由 `gen-docs` 投影到 `docs/help/ui.md` 与 `packages/demo/src/doc-data.generated.ts`。
- 闸：`test/picker.test.mjs` 新增宽度契约测试（SSR 验证不传三轴 / 96 / 80 三种根盒内联样式，并盯住 CSS 真源与 `PICKER_CSS` 注入文本都不许 trigger 持有尺寸）+ 反证用例。
- 产物链：`gen-css` 重生成 `picker-css.generated.ts`，`pnpm run build` 出 `dist/`，`pnpm run build:demo` 重建内联 PICKER_CSS 的 demo bundle。
