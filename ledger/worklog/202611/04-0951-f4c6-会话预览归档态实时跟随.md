### 三、本仓现状为什么没反应

- `SessionViewModalProps.archived?: boolean`（`src/session/SessionViewModal.ts:715`）→ `const { … archived … } = props`（`:742`）→ `isArchived = archived === true`（`:768`）：**静态 prop**。弹窗自己只订阅 chat / session 快照（`:743-750`），而 `SessionSnapshotFace` 无归档字段（`src/session/faces.ts:45-54`）。
- 归档图标（`:1106-1110`）、按钮图标与分支（`:1119-1124`）全由这一个 `isArchived` 驱动 ⇒ prop 不更新，图标不出现、按钮不变、点击走 `onClose(); openHostSession(sessionId)` 直开原会话，归档后打不开（官方 `archivedNotOpenable` 同款限制）。
- 双真源 / 双订阅：`src/ui/host-data.ts:98-125` 的 `WorkspaceListStore` 只镜像 `items`，归档集合被丢掉；demo 又自己 `ctx.inject(['workspaces'])` 订阅一次并算 `archivedSet()`（`packages/demo/src/real-sessions.ts:119-126,211-221`），`blocks.tsx:280` 每次渲染从 `state.rows` 取 ⇒ demo 恰好会刷，第三方调用方若在打开时固化 `archived` 就永久不刷。文档把这写成调用方义务（`docs/help/session.doc.ts:54-55`）。
- 结论：不是「拿不到通知」，是 core 把官方通道丢在半路，还把实时性责任甩给调用方。

### 四、两轮讨论与方案取舍

1. 第一轮给过三档（只改调用插件 / 订阅下沉 core / 点击当场判），并明确划掉「轮询 / 定时刷新 / 重建宿主路由」。用户第二轮仍点名否决轮询，并追加两条硬要求：**只有官方通道才做**、**做最合理改动而非最小改法，不合理处一并改**。
2. 澄清：第一轮表格里的「点击当场判定」不是轮询——读的是 client 内存快照（官方 `openForkSource` 原样做法），零远端请求。本轮把它并入官方方案，不再单列为「兜底」。
3. 否决：轮询 / 定时器 / 自建宿主路由 / 反复远端读 / 逼每个调用方各自订阅 / 保留静态 `archived` prop 作为并列真源。
4. 官方推荐形态 = 单一权威真源（`workspaces.list` 快照）+ 订阅派生（官方 `derive`）+ 动作前用权威快照复核（官方 `openForkSource`）。本仓按同形态落地，但不静态依赖平台模块（`AGENTS.md`：ui 入口零 `@deepseek-ai/*` 依赖），等价能力用本仓已有 `connectHost` + `useSyncExternalStore` 实现。

### 五、待拍板与边界

- 删 `archived` prop 是破坏性契约变更（0.x 下 minor 位）。用户口径倾向「最合理」⇒ 建议删；若调用方确有权威信息，统一经 `connectHost` 的源注入，不设第二真源。
- 外部脚本若**绕过宿主 registry 直接改磁盘持久文件**：不会发 `domain/changed`（唯一写口是 `dsh-workspace/lib/index.js:938-941` 的 `setState`），官方 UI 自己也不会更新 ⇒ 属非官方写入路径，官方方案不覆盖，不必为它造轮询。
- 前提是插件 client `apply` 调过 `connectHost`（本仓既有一次性接线，demo 已示范）；数据缺席时按「未归档」呈现，不编造、不写假兜底（长期原则）。
- 真机未验：本机无 DSH 宿主，以上均为源码级核实。
