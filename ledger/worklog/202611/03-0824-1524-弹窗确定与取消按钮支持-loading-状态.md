## Background

用户原话（2026-11-03）：自定义小弹窗底部的按钮（Alert 的「确定」、Confirm 的「确认」/「取消」）都要支持 loading：
点下去后消费方可能要跑异步，弹窗要转 loading 且不可关闭，等消费方处理完再恢复并关闭。

## Process

- 第一版（已作废）：`ConfirmModal`/`AlertModal` 靠外部布尔 `confirmLoading`/`cancelLoading`，命令式层在 `modal-host` 里自己跑 `isThenable` + `run` 状态机。问题：同一套语义两处实现。
- 用户 2026-11-03 拍板统一：按钮先支持异步，弹窗只管「能不能关」，alert/confirm 也走同一套，破坏性变更不算问题（内测）。
- 统一后的落点：
  - `src/ui/thenable.ts` 新建，`isThenable` 只此一份（Button 与 modal-host 共用）。
  - `src/ui/Button.ts:146` `useAsyncClick`：`onClick` 返回 thenable ⇒ 自己 `busy`（转圈 + disabled + 防连点），settle 恢复；reject 恢复后 `console.error`；`onBusyChange` 把「在跑」报出去；渲染 loading = `props.loading || busy`（**外部刷新也能点亮同一颗按钮**）。
  - `src/ui/Modal.ts:66`、`src/ui/SideSheet.ts` 新增 `busy`：遮罩 / Esc / ✕ 三条路径一起封死，是否决项，与 `closeOnMask`/`escClose` 是「与」。
  - `ConfirmModal`/`AlertModal` 变薄壳：footer 就是普通 `Button`，状态由按钮报上来汇总成 `Modal` 的 `busy`；`confirmLoading`/`cancelLoading` 保留为外部驱动（与按钮自身异步取或）。
  - `modal-host.ts` 的 `run` 只负责「跑完关不关」：返回原 promise 给 Button 转圈，resolve 后 dismiss + resolve(true/false)，reject 不关。
- 自检：`test/ui.test.mjs` 加 5 条（Button 受控 loading / onBusyChange 不落 DOM、isThenable、Modal busy 无 ✕、SideSheet busy 无 ✕）。`pnpm build && pnpm test` 245 全过；`koc-codelint` 六层全过（biome 报 `then` 属性两轮，改用 `Reflect.set` 构造 thenable）。

## Conclusion

loading 现在只有一套：按钮自己转圈（异步回调 / 外部 `loading` 两种来源取或），弹窗只认 `busy` 决定关不关；alert / confirm / 大弹窗 / 抽屉全部适用，alert/confirm 不再是特例。
`IconButton`（纯图标钮）同吃这一套：图标位换成小圈，`aria-label` 不变并补 `aria-busy`，禁用防连点；转圈期间 `Button` 的 `icon` / `iconRight` 一律让位，只留转圈 + 文字。
demo 三处可点演示已补（另加 IconButton loading 一行）。
补两处缺口（外部反馈，2026-11-03）：`InputGroup` 的 `action.onClick` 由 `() => void` 改 `() => unknown`，`run` 改为 `return action.onClick()` —— 之前返回值被吞，后置按钮的自动 loading 永不触发（`src/ui/InputGroup.ts:42`、`:144`）；`Button` 补 `aria-busy`，与 `IconButton` 同一口径（`src/ui/Button.ts:216`）。带输入框的确认框**不封** `promptModal`：命令式拿不到受控输入值、也没有校验/错误显示位，现有 `Modal + Input + Button loading` 组装才是正解，等第三个消费方再议。
`dist/` 与 `packages/demo/dist` 已重建，随 v0.22.0 / v0.22.1 发版。
