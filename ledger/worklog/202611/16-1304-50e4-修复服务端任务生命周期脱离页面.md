## Background

消费端反馈（2026-11-16，机制层、与具体业务无关）：按文档接入「服务端执行的任务」时碰到四个断点。

1. 页面重开后时间约束失效。时钟字段 `startedAt / leaseMs / maxDurationMs` 存在内存记录 `src/adv/tasks/pool.ts:152-166`；`ensure()` 每次登记写 `startedAt: Date.now()`（`:1378-1402`）；`checkServerClocks()` 只读这个本地值（`:937-955`）；`StatusRow` 不含服务端时间（`:109-117`）。全页重开后本地池为空，重登记就把时钟从零算起。
2. 盯任务的页面关闭后任务从界面消失且无人看护。`dispose()` 广播 `bye`、停心跳、清 finisher（`:1560-1580`），别页收到 `bye` 直接删分片（`:1200-1205`）；只有持 finisher 的页看护（`:880-882`）。服务端作业还在跑，前端无投影、无结算、无提示。
3. 重开后拿不到在跑任务清单。`TaskNotificationPool` 无 list/fetch（`:338-373`）；`StatusSource` 只接收已知 key（`:126-128`），key 由本地分片归集（`:884-894`）。空池 → 0 key → 不查询。文档承诺「刷新后用同一批 key 重建」（`docs/architecture/background-task-center.md:49`、`docs/guides/background-task-center.md:63`）没有机制支撑，消费方只能自己另存清单。
4. 按钮重开后失效。handler 是闭包，只存在创建页的 `runners` Map（`:768-772`），`dispose()` 清空（`:1571`）；跨页执行要创建页 ack（`:1096-1114,1207-1212`），页没了即返回 false。

根因不是四个独立 bug，而是一个错位：契约声明「服务端是真源、前端只是投影」（`docs/architecture/background-task-center.md:46-51`），实现却把任务身份、时钟、看护权、按钮闭包四样东西全绑在创建它的页面上。四条是同一设计缺陷的四个出口。

用户要求（原话口径）：参考成熟项目形成同级别方案（明确禁止打补丁），组织专家组评审直到没有剩余问题，且不能影响性能；**本轮只交付完整方案，不动代码，用户验收后再开工**。
