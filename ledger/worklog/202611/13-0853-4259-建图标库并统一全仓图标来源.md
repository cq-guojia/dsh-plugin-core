## Process

- iconfont CSS 二次实拉复核（2026-11-13）：`@font-face { font-family: "dshpc-icons-base" }`；
  `.dshpc-icons-base { font-family: "dshpc-icons-base" !important; font-size: 16px; … }` ——
  **`!important` 只在 `font-family` 上，`font-size: 16px` 是普通声明**。前一版记录写成
  「`font-size: 16px !important`」是读错，已纠正；这也解释了为何此前改字号一直有效（用户 inline / 更具体选择器直接压过它）。
  glyph 全部是 `.dshpc-i-xxx:before { content }`，共 34 条。
- 协议相对地址 `//at.alicdn.com/…` 在代码里要写死 `https:`，别原样照抄。
- 官方图标清单见 `src/types/primitives.d.ts`（41 个），**无 Calendar / Folder 以外的文件类缺口待核** ——
  日历图标官方无原件，这是「必须补我们库」的实证例子。
- 展示页落 `packages/demo/src/sections/`（已有 SectionGroup/Page 套路），远程 `<link>` 放 demo `index.html`；
  组件库自身注入是给第三方消费者的，两处互不依赖。
- 风险：远程 CSS 被宿主 CSP / 内网拦下时图标全空白 —— 先实测一次再谈退路（本地化已被用户否决）。
- 同类先例（本轮核对）：`koc-weapp-zuche-user` 并存两套 iconfont（`icon-c-` / `icon-zuche-`，各自
  `@font-face`），`src/app.tsx:11-12` 各自 import；`mp-taro-kit` 用 `SOURCES` 管 4 个包（base / base-color /
  两个 demo 包），`scripts/icons.mjs:16-30`。⇒「一个 iconfont 项目 = 一字体 = 一前缀 = 一份样式」是成熟形状。
- 官方图标真实规模（`@deepseek-ai/dsh-client-ui-primitives@0.2.0-rc.1`，装在
  `dsh-session-title-pattern/node_modules`）：`lib/types/icons/index.d.ts` 有 **94 个基础图标**，
  每个最多 3 档（`X` / `XMedium` 1.3px / `XRegular` 1px）；`IconProps = { size?: number; className?: string }`。
  本仓 `src/types/primitives.d.ts` 只声明了用过的 41 个 ⇒ 展示清单必须运行时枚举，不能写死。
- demo 不是独立预览站而是**真宿主插件**（`packages/demo/build.mjs:1-12`，client 产物是
  `__ModuleLoader__.load` 的 CJS 闭包、`@deepseek-ai/*` 保持 external），故官方图标在 demo 里可真实渲染。
- 落地时撞到的两条既有闸（都是对的设计，按它改的）：
  `test/ui-taxonomy.test.mjs:9` 规定 `src/ui` 只许 7 个类目录、新增类要用户拍板 ⇒ 图标控件放
  `src/ui/display/Icon.ts`，解析器 `src/ui/display/icon-parse.ts`（小写不进入口扫描），子路径仍是 `./ui/icons`；
  `test/no-hardcoded-copy.test.mjs` 禁界面中文 ⇒ 注册表不带 `label`，展示页直接显示库 id。
