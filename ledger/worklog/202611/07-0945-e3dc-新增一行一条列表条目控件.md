## Process

- 归类：`docs/design/structure.md:23-48` 三步判定 → 控件 / 不需业务对象 / 「只加一层外观、位置由调用方给」→ `ui/display`；`selected` 是传入的外观状态、不是组件产生的值，不命中 `:43`「同时持有值和操作 → 布局」。Card 有 `__side` 槽仍归 display（`card.css:44-50`）是先例。
- 方案：用户确认「新建可以」，采用 B —— 新建独立控件，外框复用 `Surface`（像 `Card.ts:79` 调 `surfaceClass()`），不重写第二份皮肤；只补 Card 缺的五件（整行可点+键盘、右侧操作隔离、选中态、行级 hover 开关、行高度档）。否决 A（给 Card 加轴：卡片内距 14px 与行高打架，色条 / 折叠 / panel 成负担）与 C（只给 Surface 加档：交互契约散回插件）。
- 接口：容器型 —— `children`（主内容自由排）+ `actions`（右侧槽，核心在此槽外层 `stopPropagation`）；否决结构化 `icon/label/actions` props（用户口述明确「里面就是由他自己定义」）。
- 整行不能用 `<button>`（内部要放 Button 会非法嵌套）：沿用 `src/adv/explorer/landing.ts:33-44` 的 `div[role=button] + tabIndex + onKeyDown(Enter/Space)` 与 `:56-59` 的 `stopPropagation`；行的 `onKeyDown` 须判 `e.target !== e.currentTarget` 直接 return（`src/ui/display/table-shared.ts:232` 现有缺口）。
- 命名（用户要求「以后可能还有其他的」）：定 `ListRow`，一次对齐六处 —— 组件 / Props 名、CSS 前缀 `dshpc-listrow-`、style domain `list-row`、四个文件基名、`src/ui/index.ts` 导出、`docs/help/ui.doc.ts` section.id；`List` 留给容器、`ListSection` 留给分组、`ListRow*` 留给变体。
- 样式纪律：带边 / 无边同高（`src/ui/display/surface.css:32` 保留 1px 透明边）；hover 不用 opacity（`docs/design/style.md:70-90`）；选中态压在 hover 之上（`table-plain.css:75-78`）；明暗只吃 token 的 `body[data-ds-dark-theme]` 分支。
- 首轮真机反馈三条（用户 2026-11-07）：① 上下 0 / 左右 12 不均衡，四边应等距；② 亮色 hover「根本没反应」，颜色状态要像 Button 里的灰色按钮；③ 选中态难看，不要描边、不要蓝条，只改一个单独背景色。
- 亮色 hover 失效根因（查 token 实证，非猜测）：旧值 `--dshpc-plate-hover` = `var(--dsw-static-neutral-100,#f5f5f5)`（`src/design/tokens.css:34`），常态 `tone-sunken` = 叠 6% 蓝灰 ≈ #f0f1f3（`tokens.css:19`）——白底上两者几乎同色甚至 hover 更白。`tokens.css:310` 早就记过「hover 取 plate-hover 反而更淡 ⇒ 鼠标移上去就没了」，这次是自己又踩了一遍。
- 修法：常态仍由 `surface.css:29` 的 `tone-sunken` 给、本文件不重写；hover 改 `--dshpc-active`（`src/ui/actions/button.css:57` secondary 灰按钮的 hover 色，亮色黑 18% / 暗色白 24%）；selected 改 `--dshpc-selected-bg`（`tokens.css:172,351` 双主题各自定义的「选中面」），删掉渐变 / 左侧竖条 / `--surface-border:var(--dshpc-business)`；内距 `--surface-pad:var(--dshpc-space-2)` 四边 8px 等距。
