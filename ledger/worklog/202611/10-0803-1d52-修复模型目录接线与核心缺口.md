## Conclusion

评审六条中五条属实并已修；`/options` 那条不是核心缺口（那是消费方 `dsh-task-dispatch-table` 的路由，其「守卫同口径」提醒已并入鉴权项）。改后实测：`fetch` 带 `cache:'no-store'`、刷新后第 2 次请求且 `catalog=ready`、`inject deps=["webServer"]` + handler 200、根 row 吃到消费方 `className`、旧值显示 `gone/model`。`pnpm test` 372/372、`typecheck`、`koc-codelint` 六层全过，`dist/` 与 demo bundle 已同步。

追加一轮（同日）：`ctx.get?.('llm')` 原写法 `options.getLlm?.() ?? (ctx.get?.('llm') as …)` 有两个洞——`getLlm()` 返回 undefined 时 `??` 会继续求右边，以及 ctx 失活时 `ctx.get` 本身会抛。已抽 `resolveLlm`（先走 `getLlm`，再 `try { ctx.get?.('llm') } catch`），缺失统一回 503；补两条断言（ctx 失活抛错、`getLlm` 返回 undefined 的短路分支）。`dsh-session-title-pattern/src/host/index.ts:795` 只传 `{ path }` 的接线也因此安全。验证同前，随 `v0.35.14` 发版。
