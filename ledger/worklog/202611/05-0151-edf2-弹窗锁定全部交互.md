## Background

用户 2026-11-05 原话要点：alert / confirm / 自定义弹窗里点按钮后要提交，此时**不允许关弹窗、也不允许点弹窗上任何控件**；要求
「新建一个参数，把这个和 loading 解耦」；两点硬要求：①**状态不能冲突** —— 有些控件本来就是禁用的，解锁后不能被我打开；
②**恢复初始状态** —— 下次弹一个新框、即使没传参数，也要回到未锁。补充口径：**锁定态必须有和禁用一样的视觉变化**
（鼠标移上去是禁用标识），否则用户会以为电脑坏了。

两轮设计。第一版用原生 `inert` + 整块半透明遮罩，**被用户否掉**（2026-11-05：「全部任务直接遮上，用户就觉得纯粹就是做不到」）。
最终口径（用户拍板）：控件各自显示禁用样 + 一层**全透明**点击层，不许遮任何像素。

## Process

- 承载：`Modal.locked`（`src/ui/Modal.ts:47`）—— `denyClose = busy || locked` 统一封遮罩 / Esc / ✕（`src/ui/Modal.ts:86`）。
- **只做「或」，永不写回**：这是「不与用户已禁用的状态冲突」「记住初始状态」的答案 —— 没有快照就没有还原。
  各控件在渲染时多算一个 `|| locked`：Button/IconButton（`src/ui/Button.ts`）、Input/PrefixedInput/NumberInput（`src/ui/Field.ts`）、
  Textarea、Checkbox、Segmented、Picker、DateTimePicker、Pagination。
- 第一版死路（别再走）：`inert` + 遮罩。`inert` 子树不参与命中测试 ⇒ 控件自己的 `cursor` / `:hover` 全不生效，
  只能靠整块蒙灰表达「锁住了」，观感就是界面坏了。另外 `inert` 会把面板从无障碍树摘掉。
- 透明点击层：`OverlayLockCatcher`（`src/ui/overlay.ts:27-40`）= `position:absolute;inset:0;z-index:1` 的空 div，
  只吃指针（`cursor:not-allowed`），不画任何东西；点击 `stopPropagation` 免得点到遮罩把自己关掉。
  面板要有定位锚点 ⇒ `.dshpc-modal--locked{position:relative}`（`src/ui/feedback.css`），SideSheet 自身已是 absolute。
- 重开复位：`locked` 受控、组件内不落 state；Modal 是「存在即打开」（卸载即复位），命令式每次新建 entry（`src/ui/modal-host.ts:135`）。
- 命令式：回调参数 `ctl.setLocked(bool)`（`src/ui/modal-host.ts:136-142`），entry 存 `render()` 而非固定 node（`:159`），改锁即 `flush()`；
  框关掉后调用是空操作。命令式**不收静态 `locked`**（一处开关一个入口）。
- portal 浮层：Picker / DateTimePicker 的菜单挂 body，点击层盖不到 ⇒ `useOverlayLocked()` 广播（`src/ui/overlay.ts:18`），
  两者锁定时自行 `setOpen(false)`。
- 同类件：SideSheet 一并支持，避免两个兄弟件能力分叉。
- 自绘元素的缺口（用户 2026-11-05 追加）三道补齐：
  · Tab 全吃 + 锁定瞬间 `blur` 面板内的活动元素 —— `useLockGuards`（`src/ui/overlay.ts`），只认 `.dshpc-locked` 子树；
  · 视觉上近似变灰：`:where(.dshpc-locked button:not(:disabled), …)`（`src/ui/overlay.css`）——
    **整条选择器包进 `:where()`，特异性 0**，消费方任意一条自己的规则都能盖回来；只写 `opacity` + `cursor`；
    值走新增 token `--dshpc-lock-dim`（`src/design/tokens.css`），写 1 即退出。
  · 用户两遍追问过的红线：**绝不 JS 改内联 style 再还原** —— 那才会真冲掉消费方写的东西。CSS 只是「条件成立才匹配」，
    解锁不匹配即恢复，根本没有「还原」这个动作。
- 门：`build` / `typecheck` / `test`（291 项，含 `test/panel-render.test.mjs` 的两条锁定断言）/ `build:demo` / koc-codelint 全过。

## Conclusion

`Modal` / `SideSheet` 新增 `locked`，`ConfirmModal` / `AlertModal` 透传；命令式 `confirmModal` / `alertModal` 的回调改收
`ctl: DialogControl`。锁定态 = 核心控件各自真 disabled（灰、点不动、Tab 跳过）+ 全透明点击层（挡自绘元素、禁止手势）
+ 自绘原生控件近似变灰（特异性 0、只碰 opacity/cursor、可被 `--dshpc-lock-dim` 关掉）+ Tab 全吃与锁定瞬间 blur
+ 三条关闭路径失效；**没有任何整块遮罩**。全程只做「或」、不写回 `disabled`，不传即初始未锁。
已发版 **0.32.0**（2026-11-05，`v0.32.0` tag 触发 npm 出包）。
demo 把演示挪到 alert / confirm 区，场景改成「点发布 → 提交 2 秒整框锁住 → 自动解开」。文档同步
`docs/help/ui.doc.ts`（生成 `ui.md` 与 demo 数据）与 `docs/requirements.md`（含第一版被否的经过）。
