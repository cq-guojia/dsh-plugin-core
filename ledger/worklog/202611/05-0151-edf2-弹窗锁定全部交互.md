## Background

用户 2026-11-05 原话要点：alert / confirm / 自定义弹窗里点按钮后要提交，此时**不允许关弹窗、也不允许点弹窗上任何控件**；要求
「新建一个参数，把这个和 loading 解耦」；两点硬要求：①**状态不能冲突** —— 有些控件本来就是禁用的，解锁后不能被我打开；
②**恢复初始状态** —— 下次弹一个新框、即使没传参数，也要回到未锁。补充口径：**锁定态必须有和禁用一样的视觉变化**
（鼠标移上去是禁用标识），否则用户会以为电脑坏了。

讨论结论（样式 / 架构 / 实现三视角评审）：能做，用原生 `inert` 比「核心递归给子控件塞 disabled」正确 —— 后者才是状态冲突的根源
（解锁时分不清「原本禁用」还是「我禁的」）。真风险 0 条；剩一条靠人的：本仓无 jsdom，焦点 / 命中测试只能 demo 手点。

## Process

- 承载：`Modal.locked`（`src/ui/Modal.ts:47`，文档注释 38-46）—— `denyClose = busy || locked` 统一封遮罩 / Esc / ✕（`src/ui/Modal.ts:86`）；
  面板经 `PanelSurface` 的 attrs 袋子挂 `inert: ''`（`src/ui/Modal.ts:132`）。写空串不写 `true`：React 18 的类型与运行时都不认布尔 inert。
- 状态不冲突 / 重开复位：`locked` 是**纯受控 prop，组件内不落 state**；本仓 Modal 是「存在即打开」（卸载即复位），
  命令式则每次新建 entry（`src/ui/modal-host.ts:135`）⇒ 两点天然成立，不靠消费方自觉。
- 视觉：`inert` 一个像素都不改外观，故加 `.dshpc-modal--locked::after` 遮罩层（`src/ui/feedback.css:37-41`，用 `var(--dshpc-mask)`，
  不用 opacity —— 会和控件 disabled 的 .5 叠乘）；鼠标落点在 inert 子树外落到遮罩上，所以禁止手势写在
  `.dshpc-overlay[data-dshpc-locked]`（`src/ui/overlay.css:13`）。
- 命令式：回调参数给 `ctl.setLocked(bool)`（`src/ui/modal-host.ts:136-142`），entry 存 `render()` 而非固定 node（`:159`），改锁即 `flush()`；
  框已关掉后调用是空操作。命令式**不收静态 `locked`**（一处开关一个入口）。
- portal 浮层：Picker / DateTimePicker 的菜单挂 body，不在 inert 子树里 ⇒ 新增 `useOverlayLocked()` 广播
  （`src/ui/overlay.ts:18-25`），两个浮层锁定时自行 `setOpen(false)`（`src/ui/Picker.ts:160-164`、`src/ui/DateTimePicker.ts:208-212`）。
- 同类件：SideSheet 一并支持（`src/ui/SideSheet.ts`），避免两个兄弟件能力分叉。
- 已知取舍：`inert` 会把面板从无障碍树摘掉，读屏用户此刻读不到内容 —— 已写成 `shortcut:` 注释挂在 `Modal.locked` 上。
- 门：`pnpm run build` / `pnpm run typecheck` / `pnpm test`（290 项，含新增 SSR 断言 `test/panel-render.test.mjs:53`）/
  `build:demo` / koc-codelint 全过。

## Conclusion

`Modal` / `SideSheet` 新增 `locked`，`ConfirmModal` / `AlertModal` 透传；命令式 `confirmModal` / `alertModal` 的回调改收

不碰任何子控件 `disabled`，不传即初始未锁。demo 新增「打开并锁定 2 秒」演示条。文档同步 `docs/help/ui.doc.ts`（生成
`ui.md` 与 demo 数据）与 `docs/requirements.md`。
