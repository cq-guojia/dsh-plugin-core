## Process

**① `Button` 缺底色轴 —— 是核心的缺失。**
旧 `IconButton` 有 `color` + `background` 两条轴；合并后只剩 `color`，非实心档里它同时当字色与描边色，表达不出「浅色底 + 同色系图标」。现状证据：`src/ui/actions/Button.ts:130-147` 的 `colorVars` 按档位二选一地填 `--btn-bg` 或 `--btn-fg/--btn-border`，没有第二条口子。业务现在只能在包装层手动覆盖 `--btn-bg`，每个消费方一份补丁。
契约：`background?: string`，只改底色（`--btn-bg` + 用 `color-mix(..., var(--dshpc-fg))` 派生的 hover/active），`color` 的含义按档位不变（实心 = 底色，非实心 = 字色 + 描边），两者同时给时 `background` 覆盖底色。名字沿用旧 `IconButton` 的同名轴，迁移零学习成本；不写死色值，明暗自动适配。

**② `hidden` 默认 5 分钟回收 —— 是核心的默认值错了。**
证据：`src/ui/infra/task-notifications.ts:1238` `timeoutMs = input.timeoutMs ?? (hidden ? TASK_NOTIFICATIONS_HIDDEN_TTL_MS : 0)`；到点由 `collect` / `expireLocal` 结算成 failed 并移除，而底下的作业还在跑。历史：5 分钟来自 2026-11-12 迁入时「替代手搓超时兜底」的决定（`12-1302-5333` 第 5 项），对弹窗型任务成立，对作业型任务是错的默认。
契约：`hidden` 只表达「不进默认列表」；回收只由 `timeoutMs` 表达，缺省 0（不回收）。删 `TASK_NOTIFICATIONS_HIDDEN_TTL_MS`（删导出 ⇒ 走 minor）。配套纪律：不回收意味着行与**键**都留到页面重载，登记方必须在 `finally` 里 `done/fail`，否则同键下次 `ensure` 得到 `created:false`（被当成还在跑）。

**③ `TaskBar` 动作失败静默 —— 是核心的 UX 缺陷。**
证据：`src/ui/display/TaskBar.ts:256` `onClick: () => { void taskNotifications.runAction(task.id, index) }`，返回值直接丢弃；`runAction` 在 `src/ui/infra/task-notifications.ts:1031-1040` 有三种 false（找不到/已过期、下标越界、跨页 `requestInvoke` 2s 无 ack，`:1012-1029`）。
契约：`onActionFailure?: (failure: { task, index, label? }) => void`；未传时核心 `notify(t('taskbarActionFailed'))` 给一次性提示（新增字典键）。只提示不重试——三种原因核心都自愈不了。已知坑：默认提示依赖项目挂了 toast 宿主，没挂的项目仍静默，必须自己接回调（写进文档）。

**④ 刷新与已完成 —— 拆两半，一半不做。**
不做持久化。判据是「作业的真身在哪」：后台作业跑在 host 的会话里，池只是这一页的展示镜像。把池写进 sessionStorage，刷新后回来的是有行、无执行者的僵尸：方法表在旧页面里已清空 ⇒ `runAction` 永远 false、`done()` 永远不会来 ⇒ 条目永远停住且不会自己消失（没人调 settle）。这比"什么都没有"更糟，并与上一轮定的「不谎报仍在处理中」直接冲突。
替代（这才是 key 幂等要兑现的场景）：刷新后由业务按宿主那边的真实状态重新 `notifyTask.ensure({ key })`，接回 host 事件；核心保证同键不重复、跨页照旧拒绝。配套 `startedAt?: number`（仅影响计时起点，大于当前时间按当前算），否则重登记后显示「已执行 00:00:03」而实际跑了三分钟——假数据。
做已完成留存：`settle` 不再直接丢，移入独立数组 `finished`（`{ ...record, status: 'done'|'failed', reason?, finishedAt }`），跨页按 id 合并，保留到 `dismiss(id)` / `clearFinished()`，另加条数上限（初定 20）截断，不设 TTL。独立数组的原因：键在 settle 时释放，判重只看运行中的 `tasks`，两者不能混。已完成行不给动作按钮（方法表已没了，给了就是假按钮）。
