## To Do

**A. 确认是我们的问题、该修（15 条）**

P0：
1. **P0-1 三处代码接完不会弹卡**：`connectTaskCenter` 首次接线才补默认 host + 订阅 SSE，但三处代码示例（start/mountUI/TaskBar）没这一步。证据 `src/adv/tasks/api.ts:173-181`、`docs/api/task-notifications.doc.ts:29-54`。
2. **P0-2 mountTaskUI 收 project/groups 但不用**：只读 handlers/onSettled，`onSettled` 未按过滤条件筛。证据 `api.ts:235-242`。
3. **P0-4 origin 判定错**：`isOrigin` 用 `panelId` 判发起页；服务端执行模式乐观/服务端记录都没有 panelId → 恒 true（origin 失效），本地模式切面板又错判。证据 `api.ts:139-141,221-228`、`model.ts:106-119`。
4. **P0-5（部分）按钮发起页判定没实现**：按钮显示只看本页有无同名 handler，handler 全局共享，无法判"发起页"。证据 `api.ts:143-152`。sessionStorage 部分移交"待定夺"。
5. **P0-6 args 编译不过**：`interface CloseTaskInput` 传给 `Readonly<Record<string, unknown>>` 报 TS2322（interface 无索引签名）。证据 `model.ts:113`；已用核心 TS 实测复现。

P1：
6. **P1-1 broadcast plugin/global 不在发送侧隔离**：两种范围发同一条靠订阅端过滤，与 worklog:99 拍板"channel 名分开"不符；`scope:'plugin'` 不传 project 时比较恒不成立、一条收不到。证据 `api.ts:162-167,265-280`。
7. **P1-3 清理函数关错连接**：`connectTaskCenter` 返回的 off 关的是全局 `streamConn` 不是自己那条，重复接线后先卸载的关掉别人的流；显式传 undefined 字段还会覆盖之前的 streamUrl/submitUrl。证据 `api.ts:181-191`。
8. **P1-4 handler 全局按 id 覆盖**：同标签页共享 Map 只按字符串 id 索引，两个插件都用 open-log/retry 互相覆盖。worklog:40 列明要补未补。证据 `store.ts:141-152`。
9. **P1-5 handler 抛异常不兜**：`coordinator.press` 直接 `handler(task)` 无 try/catch，与同文件 safeCall/emitSettled 不一致。证据 `coordinator.ts:187-195`。

P2：
10. **P2-1 serveTaskSubmit authorize 在 try 外 await**：抛错请求挂死无响应。证据 `src/host/task-submit.ts:39-54`。
11. **P2-2 只覆盖一个默认层不补另一个**：hadDefault 用 `||`，只传 deliverToast 时 deliverNotify 永久静默。证据 `api.ts:174-180`。
12. **P2-4 isTaskRecord 不校验 settledAt + SSE 解析窄**：settledAt 字符串按 NaN；解析只认 `\n\n` 和第一条 `data:`，不兼容 CRLF/多行 data。证据 `api.ts:99-110`、`stream.ts:41-47`。
13. **P2-5 claimSettled 注释与实现不符**（纯注释）：注释说"只有更晚新结算才能再拿声明"，实现只查 key 存在 + 靠 running upsert 删除重置；逻辑正确、注释写错。证据 `store.ts:101,169-176`。
14. **P2-6 TaskActionFailure.index 注释错**：仍说 actions、传的是按 when 过滤后下标。证据 `TaskBar.ts:389-433`。
15. **P2-7 close 后重连等待最长 4 秒**：`close()` 不打断重连 sleep。证据 `stream.ts:94-97,101-105`。

**B. 不合理 / 符合已拍板，不改（3 条）**

- **P0-3 TaskBar 显式传 handlers + 没 handler 不画按钮**：是消费方旧文档口径，已被用户 2026-11-18 拍板覆盖——"所有按钮回创建页执行、跨项目跨页都点得到、不隐藏不置灰"（worklog:29、:98）。新架构 handler 在 client 内存靠 `Symbol.for` 全局共享，TaskBar 不接 handlers prop 是架构必然；"点了提示失败"正是拍板要的"不隐藏、点了明确告知不可用"。仅 worklog:98 标注一个张力（"用户说不用提示" vs "点了提示不可用"）待用户定。
- **P1-2 notify 不写 broadcast 时本页弹卡、与 toast 同配出两张卡**：符合需求定义——"scope = 谁弹、broadcast = 走不走跨页通道"（消费方需求文档:126-128），两通道独立、消费方都配就都弹，非核心缺陷。
- **P1-6 onSettled 依赖服务端额外发 task-notice、subscribeNotices 可选无兜底**：三流隔离 + project 只投影不弹卡 + onSettled 只由 notice 驱动，是用户 2026-11-19 亲自拍板的根治方案（修"刷新重弹历史通知"）；"没兜底"是故意的，服务端必须实现 subscribeNotices（文档 source 示例已列）。
