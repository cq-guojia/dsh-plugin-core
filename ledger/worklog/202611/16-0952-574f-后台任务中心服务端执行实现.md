## Background

用户确认后台任务走 C 方案：任务一开始就进后台任务中心，服务端持任务真值，前端任务中心只作投影；刷新 / 关页后端作业继续跑，回页面按稳定 key 从服务端重建。此前三个台账（幂等登记、四处收尾、分层重排）是已交付的前置工作，与本任务非同一件事，已结案。

方案经专家组对照四个成熟项目核实并定稿：Temporal（Workflow Id 幂等 / 冲突策略 / ID 不放敏感信息）、SQS（visibility timeout 可续但 12 小时硬上限不重置）、BullMQ（锁到期 stalled 重投、at-least-once、业务必须幂等）、Kubernetes Job（activeDeadlineSeconds 总限 + ttlSecondsAfterFinished 终态清理）。设计契约已写进 `docs/architecture/background-task-center.md`，消费方接入写进 `docs/guides/background-task-center.md`。
