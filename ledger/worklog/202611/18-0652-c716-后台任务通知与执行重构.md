## Background

用户 2026-11-18 拍板：原来的后台执行整套做错了 —— 一直以为是「通用的后台执行结果/状态中心」，实际宿主侧只有**会话**一种执行载体，没有通用后台执行。要求按消费方（dsh-task-ledger）给的使用代码倒推，彻底重构核心的后台任务通知与执行。

需求来源（消费方视角，不是实现方案）：`/code/dsh-plugins/dsh-task-ledger/ledger/worklog/202611/17-1654-6159-后台任务通知与执行方案.md` —— 该文件声明「API 名字、类型形状、内部机制都由核心决定」，只规定消费方要写的三处代码与验收口径。用户口述补充的需求要点与该文件一致，并强调：

- 消费方只写三处：① 注册 handlers（`mountTaskUI`，列表与 Toast 共用，按钮 id → 本页函数）② 每次发起 `startTask`（标题、通知配置、按钮声明全扔给核心）③ 挂 `mountTaskList`（画面全归核心，消费方不画）。
- 两类通知：**广播通知**（无按钮，广播参数，scope 可选「只当前插件」还是「所有插件」，收到怎么处理由消费方自己监听决定）与**长连接通知**（任务 UI 带按钮，按钮事件只在发起方插件注册）。Toast 是终态通知，成功/失败各自可配要不要通知、要不要按钮、scope（默认只自己项目，要全部就全部）。
- 核心后台执行支持三类：① 开一个 share 去执行 ② 执行一个会话 ③ 调用插件方 host 脚本（会给脚本相关东西）。基本满足要求。
- 心跳**完全在后端执行**，核心不写心跳，只管把方法扔进来。
- 渐进式任务（一个会话处理很多节点）要能更新进度「当前在干嘛」，记下任务的最后更新时间与最后更新的一段话。

### 方案 v1（存档：评审前草案，已被 v2 覆盖）

**定位翻转**：核心从「通用任务状态中心」改为「**后端执行 + 通知 + 控件**」。状态真源、心跳、判死、进度推进**全在服务端**；前端只做登记、渲染、转发按钮，不轮询、不判死、不算租约。消费方是「后端执行」的一方，核心是它的通用接线层。

**三处消费方代码（契约外形，以消费方 worklog 三块为准，名字由核心定）**：
- `startTask(input)` → 登记并返回；`input = { project, group, title, key, kind, args, toast?, notify?, rowButtons? }`。`await` 等登记成功，不等跑完。`key` 同项目幂等（就地更新）。
- `mountTaskUI({ project, groups, handlers, onSettled })`：① 注册按钮 id→本页函数（列表与 Toast 共用一份）② 订阅终态弹卡 + 跑 `onSettled`（只刷消费方自己的数据）。`project:null/省略` = 收所有项目。
- `mountTaskList({ project, groups, handlers })`：核心画列表行、筛选、进度、按钮；消费方不传渲染配置。
- 对外出口：`adv/tasks` 给 `startTask` / `mountTaskList` / `TaskNotificationRecord` 等；`ui/task-ui` 给 `mountTaskUI`（按消费方文档的两条 import 路径落地）。

**执行三分派**：`kind` 用命名空间前缀区分 share / session / host-script 三类执行器；`args` 纯数据（过不了进程边界，不带函数）。核心提供 host 侧执行器注册与 SSE 推送适配；执行体把进度/终态推给服务端，服务端经自建 SSE 下发。**三类是否都有宿主 API 支撑尚未核实**（本地零 `@deepseek-ai/*`，按 DSH 规则 npm view + pack 读实现后再定），这是开工第一道闸。

**通知三通道，互不混用**：
1. 广播 `notify.<state>.broadcast`：`'plugin'` 同项目 / `'global'` 同宿主所有插件 / 不写不发。纯参数、无按钮，接收方自己监听处理。范围限同浏览器同域名（同源），跨浏览器/域名不考虑。
2. Toast `toast.<state>`：`{ title?, button?:{id,text}, scope:'all'|'origin' }`；成功/失败各自独立、整态省略=该态不弹；`all` 所有页弹（含跨项目）但按钮只在发起页显示，`origin` 只发起页弹。
3. 列表行按钮 `rowButtons:[{id,text,when}]`：`when ∈ running|done|failed|always`（缺省 always），同 id 可按状态重复声明；点击统一回创建页 `handlers` 执行，**任何项目都点得到，不隐藏/不置灰**。

**进度显式字段**：`TaskNotificationRecord` 加 `updatedAt`（最后更新时间，服务端给）+ `lastMessage`（最后一段话）+ 可选数值进度字段；由服务端上报、经 SSE 推到前端投影，UI 显示策略不在本轮契约内。

**长连接**：自建 SSE（`webServer.register` + client `fetch` 流解析），服务端是推送源；断线由客户端退避重连。不用宿主 `follow()`（仅领域状态）/ `remote.$on`（仅审批瀑布）——两条都不接插件自定义任务数据。

**整套删除（旧实现）**：pull 心跳 `setStatusSource` / `pollStatus` / 双时钟租约 `leaseMs`/`maxDurationMs`/`deadlineAt` / tombstone+version 客户端调和门 / 状态源 `(keys)=>StatusRow[]` / 业务心跳定时器 / 自建命令 token+version+invoke 的服务端幂等缓存。保留的只有可被新方案复用的：稳定 key 幂等登记、跨页 handlers 回创建页执行（id+reqId 的 invoke/ack，非心跳）、事件总线、多副本收口。

**验收口径**：以消费方 worklog「核心需要满足的需求」表 7 条为准；测试 import `dist/`，先 build；build → test → typecheck → build:demo 全过；产物入库；文档改 `.doc.ts` 真源。

### 二、完整契约（v2）

- `startTask(input)`：`{ project, group, title, key?, kind, args, toast?, notify?, rowButtons? }` → Promise（等登记）。`kind ∈ shell:*/agent:*/executor:*`；`args` 纯数据；`toast/notify` 各含 `success/failure` 两态；`rowButtons:[{id,text,when}]`，`when ∈ running|done|failed|always`。
- `mountTaskUI({ project, groups, handlers, onSettled })`：注册 id→handler（共用一份）+ 订阅终态弹卡 + `onSettled(task,outcome)`（可选，只刷自己数据）；`project:null` 收所有。
- `mountTaskList({ project, groups, handlers })`：核心画行/筛选/进度/按钮，消费方不传渲染配置。
- `subscribeNotifications({ project?, scope:'plugin'|'global', handler })`：广播监听出口，收到纯数据 `message/detail` 自己处理。
- 出口：`adv/tasks`（startTask/mountTaskList/TaskNotificationRecord/subscribeNotifications）、`ui/task-ui`（mountTaskUI），全登记闸。
