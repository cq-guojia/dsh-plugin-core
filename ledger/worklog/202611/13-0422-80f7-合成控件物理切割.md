## 共识（2026-11-13 用户拍板）

1. **一个 npm 包、一个版本、一次安装全部不变**；只是多开 per-component 子路径（门牌），不发 N 个包。
2. `./ui` **整包入口保留**：想全引就引它，接受产物大；要单引就引 `./ui/<控件>`，只带那一块 + 它真实依赖的块（如会话预览自带文件预览与侧边栏属合法）。
3. 整包入口是**纯 re-export 转发表（链接），不是 copy**，真源只有一份。证据：`dist/ui/index.js:5-55` 共 56 行、全是 `export … from './xxx.js'`，零实现；`dist/ui/inputs/Field.js:2` 自述「全站唯一实现」。CSS 字符串常量同理，多个入口 import 同一个 `*-css.generated.js`，打包器按路径去重。
4. **样式链路不动**：源码真 `.css` → `scripts/gen-css.mjs:29-67,115-123` 用 `JSON.stringify` 编译成 `*.generated.ts` → tsc → 运行时注入，这条早已封装好。本次只让每块自带自己那份字符串常量，不再经聚合点。
5. **严格照成熟项目**：核实 `@mui/material@5.16.7/index.js` 整包入口就是 `export { default as Button } from './Button'` 这类纯转发表；MUI 官方默认 path import、Rad UI 禁 mega-barrel。不自创方案。
6. 消费方引用路径后置迁移，由用户安排；库内 demo 展示全部控件，走整包入口属合理用法。
7. 本轮**不 bump、不打 tag、不 commit**（用户未要求提交）。

## Process

现状（只读审计 + 不落盘 esbuild 探针，均 2026-11-13）：
- `src/ui/index.ts:5-305` 是 48 出口 mega-barrel，`dist/ui/index.js:5-55` 仍 47 条静态 re-export；`package.json:21-63` 无 per-component 子路径、无 `./ui/*` 通配。
- `src/ui/infra/controls-css.ts:10-27` 是 16 出口 CSS 聚合 barrel，18 个控件从它取常量；历史上 `css.ts:5-9` 已自述过同类问题（全量 71.7 KB 样式文本）。
- 实测（esbuild 内联 bundle、react external，metafile）：`import { Input } from ./ui` 147773 B / 解析 118 文件 / 实际进产物 14 个 ui 模块，含 `actions/Button.js`、`feedback/Loader.js`、`display/FieldHint.js` 及三份别控件 CSS；`import { Picker }` 242548 B / 18 个 ui 模块，含 `inputs/field-css.generated.js`（Input 的皮肤）；`import * as ui` 657613 B。具名引入下 tree-shaking 能去大块，但模块图仍全量解析，且横向依赖闭包确实把别的控件带进来。
- 成熟库对标：MUI《Minimizing bundle size》以 `@mui/material/Button` 路径导入为官方默认并用 ESLint `no-restricted-imports` 禁 barrel；Rad UI《Barrel export policy》禁 mega-barrel、per-component entrypoint 为默认；Radix 一组件一 npm 包（也提供可摇树的统一包）；antd / antd-mobile 在不支持摇树时手动 `es/<component>`；Vercel《How we optimized package imports in Next.js》量化 barrel 代价并把 named import 改写成 per-component path；Node.js `exports` 支持显式枚举子路径。
- 专家组三视角评审（分发形态 / 依赖图 / 宿主运行时）结论：① 多包 monorepo 会炸双包同号发版链与 demo 内联，取单包 + 显式枚举子路径；② 拆 CSS 聚合 barrel 不动 `style-kit.ts` 的域顺序/幂等/注入器即安全，但 CSS 注册不得从 render 期提前到入口；③ `sideEffects` 用精确数组把 `official.js` 标 true，不要改成消费方显式调用（会让 `skin:'host'` 静默退化）；④ 真实消费链绕过 npm exports（demo 直引 `../../dist`、调试期 git 路径安装），自检必须验 dist 文件而非只验 exports 表；⑤ per-entry 自检放 `test/`，CI 需补 `pnpm test`。
- 本仓既有拍板可援引：`docs/design/structure.md:10-11`「结构优先于兼容 —— 消费方该改就改，不为保持旧 import 而选不合理结构」。
