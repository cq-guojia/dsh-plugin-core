## Background

用户 2026-11-06 拍板两件事，层级那条已单独做完，本任务是第二条：

> 「遮罩不挡左侧菜单：你把前因后果以及现在已经预知的可能影响写清楚，去建一个新任务」

起因：会话预览弹窗里点图片放大，官方 `ImageLightbox`（`z-index:1000`，body portal）被我们
`--dshpc-z-modal:1070` 的遮罩压住。由此分成两件事：① 我们整条浮点阶梯必须低于官方 1000 档（**已
改完**，900/920/940/950/960/970，见 `src/design/tokens.css`）；② 本任务 —— 遮罩覆盖范围（作用域）。

用户的原话逻辑：

- 「我们是频道下面的一个页面」⇒ 遮罩不该盖住宿主左侧导航，切走再切回资料应该还在；
- 「甚至我们的这种模态居中都应该排除左边那个菜单，应该在我们的页面居中，包括我们的那些什么拓
  啊什么什么的」⇒ 居中基准、抽屉、Toast 等同类浮层应一并只作用于本页窗格。

## Process

现状与已知影响（2026-11-06 核实，库 0.2.2-rc.1 + 本仓 HEAD）：

- **现状**：`src/ui/infra/overlay.css` 的 `.dshpc-overlay` 是 `position:fixed; inset:0` + `z-index:
  var(--dshpc-z-modal)` ⇒ 全视口，左侧导航也被压暗。右栏让位已有 `--dshpc-page-inset-right`（由
  `src/ui/layout/panel-dock.css` 的 PanelDock 发布），**左侧没有对应变量**。
- **影响 1（选 left inset 方案）**：侧栏宽度没有公开变量，只能从宿主 DOM 探测（容器 rect / 侧栏元素
  宽）；侧栏折叠、拖拽调宽时要跟着更新，宿主改版即失效。
- **影响 2（选 absolute 方案）**：遮罩随挂载容器滚动、只覆盖容器内容高度；要给挂载容器
  `position:relative` 并处理滚动与高度，否则长列表里遮罩会「只盖一段」。好处是「本页 = 遮罩边界」
  天然自洽，居中基准跟着窗口走。
- **影响 3（状态泄漏，必办）**：遮罩不盖侧栏 ⇒ 弹窗开着时可点导航切宿主视图 ⇒ 插件可能被卸载，而
  `dispose()` 只在 `onClose` 调 ⇒ `sessions.retain` 泄漏（会话 scope 不回收）。
- **影响 4（连带面）**：居中口径一变，抽屉 / Toast / 收起耳朵的位置都受影响（共用 overlay 与 inset 体系）。
- **影响 5（非本任务引入）**：宿主切页再切回，插件大概率重新挂载 ⇒ 弹窗默认关闭、内部状态不保留；
  用户期望的「资料还在」需要宿主侧保活或我们落盘，属另一个决定。
- **已定的层级事实**：官方 `Modal` / `ImageLightbox` = 1000（body portal），`Menu` / `Toast` = 1100；
  我们阶梯已全部降到 1000 以下，官方浮点恒在我们之上（`src/design/tokens.css` 注释已写明）。
