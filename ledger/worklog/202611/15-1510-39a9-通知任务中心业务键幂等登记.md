## Background

2026-11-15 业务方（dsh-task-ledger 侧）反馈：把「收至后台」当成登记点，用户每收一次就 `notifyTask` 一次，同一个作业被登记成两条，各自计时、结束时发两条完成通知。他们的诉求原话收敛成三件事：按业务键幂等登记、记录上带这个键供读侧判断、跨页同键要有明确态度。

用户随后把需求说成更根本的一句：**「我有些东西得放到里面，可能得反复放，它打开了，我还得放，打开了还得放；我不想自己去处理，每次还得记得哪个放了、哪个没放」**，并追问「这个 ID 怎么定义，是我随机生成一个吗」。⇒ 要的不是「防重复报错」，而是「反复 ensure 也不会多一条」，且身份必须由调用方给。

现状（改动前）：

- `register` 每次都无条件新建 id，记录上没有任何调用方身份 —— `src/ui/infra/task-notifications.ts:1145`、记录结构 `:83-112`；
- 池对外只有 `runAction(taskId, i)` / `settleLocal(reason)`，没有「按身份取回句柄」的入口 `:265-293`；
- 可见任务 `timeoutMs` 缺省为 0（永不回收）`:1136`，所以丢句柄之后那条只能永远挂着。

判定这是核心该做的事：去重、身份保管、跨页冲突换任何插件都是同一套机制；业务自建「键 → 句柄」表等于给池再记一份影子状态，且解决不了跨页。

## Process

**调研（2026-11-15，均查原文）**

| 项目 | 键怎么来 | 已有同键 | 正在跑的同键 | 上下文 |
|---|---|---|---|---|
| Temporal Workflow Id | 调用方给，带业务含义 | `WorkflowIdReusePolicy`（默认 Allow Duplicate） | `WorkflowIdConflictPolicy`：Fail（默认）/ Use Existing / Terminate Existing | 中央服务端 |
| Stripe `Idempotency-Key` | 客户端给（建议 UUID） | 重试返回首次保存的响应 | 与并发请求冲突 → 不缓存、报错（官方页未写死状态码） | 服务端 |
| TanStack Query `queryKey` | 调用方给结构化数组 | 命中缓存 | 并发同键共享同一个 in-flight promise | 单页 |
| Sonner `toast(msg,{id})` | 调用方给，缺省随机 | 就地更新同一条 | 同上 | 单页 |
| Chrome `notifications.create(id)` | 调用方给 | 先 clear 再 create（替换） | 同上 | 单扩展进程 |
| Web Notification `tag` | 调用方给 | 可被程序替换 | — | 单 origin |
| Web Locks / `docker --name` / VS Code command id | 调用方给 | 报错 / 互斥 | 互斥 | 跨上下文 |

两条从原文掉出来的结论：① Temporal 的保证就是「同 ID 同时最多一个在跑，Close 后可复用」；② **所有「同键替换」的先例执行体都在同一上下文**，所有跨上下文的先例都是互斥或报错 —— 这判死「跨页复用返回句柄」（作业在别的页，给句柄等于给假按钮）。

**裁决**

- 键由调用方给、必须确定性（随机值 = 永远对不上 = 永远重复）；结构化 tuple 归一化成稳定串，避免手拼分隔符撞键（TanStack 同款理由）。
- 同页命中 → 就地 patch（只覆盖本次给了的字段）并返回**同一个**句柄；跨页命中 → 抛 `TaskNotificationConflictError`。
- `claim()` 返回 `{ handle, created }`：`created === false` 的调用方不得再起第二份活（Temporal Use Existing 的同款信号）；`notifyTask.run` 撞键 reject 且不调用 `work()`。
- 键随记录离池释放；唯一性范围 `(project, key)`，`group` 不参与。
- 键进快照与界面，照 Temporal 的警告：不放敏感信息（不做运行时检查）。
- 跨页判重看已合并快照，有「新开页尚未收到对端分片」的窗口（约一个广播往返）—— 写进文档已知边界。

**已核的坑**：Stripe 的 409 只见于第三方对照表，官方 Idempotent requests 页只写「与并发请求冲突」；Temporal 的 `Terminate if Running` 在它正文与列表里自身不一致。
