## Background

用户原话（2026-11-12）：「把我们现在这个站用到的所有类似于这样的功能，你给我拟个列表，然后我们一个一个把它给挪过来。原来的所有类似于的功能全是废弃。」

触发它的背景是同一天通知任务中心的一整轮演进：先加 `notifyTask` / `notifyTask.run` 门面（`src/ui/infra/task-notifications.ts`），再补 `settleLocal()` 与 Web Locks 失联清理，再做两级分组（协议 2），最后拆出常驻任务与纯广播（`notifyMessage`）并支持 `icon` / `iconSvg`。这一路暴露出同一个结构性问题：

- demo 站（`packages/demo`，4477 行 section 代码）里每个演示主题都自成一套，控件、文档、示例、状态各自实现；
- 这些能力一旦要被真实插件复用，就得在 core 里重写一遍，而 demo 里那份旧实现留在原地，形成两套真源；
- 用户要求：先列清单，再逐个迁进 core，**原来那些同类实现一律废弃**（不是并存、不是兼容层）。
