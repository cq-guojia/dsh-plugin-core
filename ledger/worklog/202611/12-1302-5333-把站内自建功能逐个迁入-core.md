## Background

### 一句话：这个任务做什么

把三个真实插件（tdt / stp / ledger）里**自己手搓的「通知任务中心」同类实现**，逐个换成 core 的 `notifyTask` / `notifyMessage` / `taskNotifications`，然后把原实现**删掉**（不是并存、不是兼容层）。

### 靶子只有一套机制，别扩大

对比对象是 core 的 `src/ui/infra/task-notifications.ts` 这一套（外加它的贴身底层件 `src/ui/infra/ticker.ts`、`src/ui/feedback/Loading.ts#RunningBlocks`、`src/ui/feedback/Toast.ts#notify`）。

判据只有两条，**满足任一条就是本任务的对象**：

1. 自己维护「后台长任务的运行态」——本地 `busy` / `step` / `closing` 状态、手搓超时兜底 `setTimeout`、组件卸载或切页就断、结果只靠一次性 toast 汇报；
2. 自己渲染一次性提示——绕过 core 直接拿官方 `Toast`、或「state + 自增 seq + useEffect 重播」这类手写 toast 状态机。

### 明确不是本任务（这几轮反复被误解，写死）

- **不是**「去找哪些东西是 core 该提供的」（页面骨架、i18n、文档渲染、宿主数据面……都跟本任务无关）；
- **不是**「把 demo 站每个 section 重写一遍」；
- **不是**「给 core 加新能力」——core 缺的能力另开任务，本任务只做「把已有实现搬过来并删旧的」。
