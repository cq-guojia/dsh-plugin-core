# dsh-plugin-core 需求

> **本文只记「范围」和「还没有归属的结论」。** 一条结论写进它该在的文档之后就从这里删掉 ——
> 所以这个文件应当越写越短；它变长说明有人在往里堆过程稿。
> 槽位与各文档位置见 `docs/README.md`。

## 0. 一句话

把 DSH（DeepSeek Harness）插件反复要写的东西收敛成一个 npm 包，以后写新插件按文档引用，
不再一个个仓库抄样式、抄文件浏览、抄日期格式化。

## 1. 服务对象（最重要的一条）

**这个包服务的是「以后要写的每一个 DSH 插件」，不是现有这三个。**

现有三个插件（`dsh-task-dispatch-table` / `dsh-session-title-pattern` / `dsh-task-ledger`）的定位是：

- （a）需求会反复出现的**证据**
- （b）第一批消费者

⇒ **判据不是「三家都抄了什么」，而是「任何一个 DSH 插件大概率都要用到什么」。**
三家没有、但未来插件一定会用到的，照样进；三家都有、但属于业务的，照样不进。

## 2. 范围

| 子包 | 干什么 |
|---|---|
| `design` | token + 样式注入器工厂（零 React） |
| `ui` | 控件，7 类：动作 / 录入 / 展示 / 反馈 / 布局 / 导航 + `infra`（不是控件的公共底座） |
| `utils` | 纯方法（零 React / DOM / 宿主） |
| `adv/explorer` | 文件浏览成品（面板 + 预览 + 两个命令式能力） |
| `adv/session` | 会话预览成品 |

分类判定、目录、依赖方向、demo 分区 → `docs/architecture/structure.md`（唯一真源，本文不复述）。
控件怎么用、props 长什么样 → `docs/api/` 与 TypeScript 声明。

## 3. 不进（业务，各插件自己写）

- 设置页骨架（**候补**：等出现第二个愿意用它的消费者再抽）
- `host` 子包（已取消）
- `llm/` 独立子包（已取消，ModelPicker 进 `ui`）
- 业务件：业务选择器 / 日历 / 业务 token / 页面几何 / 插件私有路由 / DB 表

## 4. 只有本文记着的约束

这几条在别处还没有落点，先记在这；写进归属文档后删掉。

- **多语言**：核心提供的固定提示语由核心自己翻译（内置中英 + `setLocale`）；插件界面文案插件自管。
- **依赖注入**：不传整个 `ctx`，只传需要的那一小块能力 —— 传了整个就把包和宿主版本焊死。
- **第三方依赖**：默认优先官方件；明显更好的包可以引，但必须先说明理由、经用户拍板，
  且作为内部依赖封装、不 re-export，消费方看不见第三方。

打包产物、样式注入工厂化、明暗判据、注入顺序（不采用 `@layer`）→ `docs/development/style.md` 与 `AGENTS.md`。
